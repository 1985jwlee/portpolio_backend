# Feature: 백엔드 역량 증명형 포트폴리오 사이트

> **위치**: 이 명세는 `README.md` 로드맵의 **첫 마일스톤(M1)** 이다. 바둑·KataGo·타임딜·결제·풀필먼트·CS 채팅은 이 명세의 범위 밖이며 후속 Phase 가 맡는다. **구현 순서는 M1 → 타임딜(Phase 3) → Phase 4 → Phase 5 → Phase 6a → … 바둑(Phase 1·2)은 마지막**이다(README 로드맵의 ‘구현 순서’ 열, `docs/design/phases/00` D24; Phase 번호는 식별자로만 유지). (초기 로드맵 문서는 요지를 README·ADR 에 흡수한 뒤 삭제했다.) 결정의 근거는 `docs/adr/` 이다(특히 ADR-002·003·013·031).
> **상태**: **확정 대기 — 사용자 확인 필요.** 사용자가 “확정”을 명시한 적이 없다(끝의 *확정 체크리스트* 참고). 설계(ADR-001~047, `docs/design/` 00~15·`features/`·`phases/`)가 이 명세보다 앞서 진행되어, 2026-11-04 에 설계에서 도출된 요구를 FR/AC 로 **역반영**했다(FR-013·025~028·036~038·062~063·081·090~093·100~102·110~111·120~121, AC-018~038, 접근성·브라우저·가용성 NFR). 수정 요청은 언제든 반영한다.
> **출시 계획(제안)**: FR 마다 출시 층(A·B·C)을 표기했다. **A+B 를 M1 첫 공개, C 는 M1.1 로 이어서** 낸다(설계는 동일, 출시 시점만 분리). 사용자가 “전부 한 번에”(R7-Q3, ADR-013)로 되돌릴 수 있다. ADR-013 의 ‘전부 한 번에’는 ‘성능 수치는 측정 후에만 쓴다’는 원칙과 한 묶음이었고, 이 출시 분리는 **사용자의 명시 답변이 없어 내가 권장안으로 정한 제안 상태**다(확정 체크리스트에서 확인).

## Overview
채용 담당자·방문자에게 공개되는 포트폴리오 사이트이며, **사이트 자체가 백엔드 작품**이다. 자기소개·아키텍처 설명과 함께, 방문자가 직접 써보는 라이브 데모 3종(이벤트 흐름 시각화 · 실시간 기능 · 운영 지표 대시보드)으로, 그 소재는 방명록+이모지 반응이다. 이를 통해 outbox 기반 이벤트 처리·실시간 전달·관측성 역량을 동작으로 증명한다. 백엔드와 프론트엔드를 함께 설계하며 웹 전용이다. **완전 무료(0원·카드 청구 위험 최소) 자체 호스팅**이 제약이다.

## Functional Requirements

> **출시 층** (제안, 삭제 없이 표기만): **A 핵심 데모** — 방명록·반응, outbox/inbox, 선점·버전, 이벤트 시각화, WebSocket, 지표 대시보드, 정적 폴백, 신원·OAuth, 접근성·SEO·개인정보 안내. **B 운영 성숙도** — 쓰기 잠금, dead 재투입, 읽기 모델 재구성, 감사 로그, 서버 로그 4종, 신고 메모 암호화, 백업·복구. **C 후순위(M1.1)** — 보관 정지, 운영 상태 파일·Discord 경보, 세션 일괄 폐기, 필드 키 회전, 비밀 스캔, 사고 대응 절차, 컬럼 등급 검사, 백업 키 분리. (지정 분류에 없던 FR-025·026(신고 메모 암호화·열람)·FR-081(백업·복구)은 B 로, FR-028(멱등 쓰기)은 A 로 내가 배정했다.)

### 사이트 콘텐츠
**FR-001 자기소개** `[층 A]` — When 방문자가 자기소개 페이지를 열면, the system shall 경력·연락처를 선택된 언어(ko/en)로 표시한다.
**FR-002 아키텍처 설명** `[층 A]` — When 방문자가 아키텍처 페이지를 열면, the system shall 이 사이트의 구성(outbox 흐름, 스택 선택 이유, 호스팅 구조)을 선택된 언어로 설명하고 각 데모로 연결한다.
**FR-003 저장소 링크·CI 배지** `[층 A]` — The system shall 공개 GitHub 저장소 링크와 CI 상태 배지를 표시한다.
**FR-004 언어 전환** `[층 A]` — When 방문자가 언어를 바꾸면, the system shall 모든 화면 문자열을 ko/en 으로 전환하고 선택을 유지한다.

### 방문자 신원
**FR-010 익명 세션** `[층 A]` — When 방문자가 처음 접속하면, the system shall 로그인 없이 익명 세션을 발급하고 세션별로 데이터를 격리한다.
**FR-011 GitHub 로그인** `[층 A]` — When 방문자가 GitHub 로그인을 하면, the system shall 영구 신원과 표시 이름을 부여하고 이후 쓰기를 그 신원에 귀속한다.
**FR-012 관리자** `[층 A]` — Where 로그인한 GitHub ID 가 허용목록(1명)에 있으면, the system shall 숨김 처리 등 관리 권한을 부여한다. (ADR-008, design/06 §5)
**FR-013 세션 일괄 폐기** `[층 C]` — When 운영자가 세션 폐기를 실행하면(전체·사용자·세션 단위), the system shall 대상 세션을 즉시 만료 처리하고, 이후 그 쿠키의 요청을 새 익명 세션으로 처리하며 해당 private 연결을 닫고 감사 로그에 남긴다. (ADR-028, F10 ID-11, design/13)

### 방명록 + 반응 (데모 도메인)
**FR-020 글 작성** `[층 A]` — When 방문자가 길이 제한 이내의 글을 제출하면, the system shall 글과 outbox 이벤트를 **한 트랜잭션**에 기록하고, 응답에 생성된 글 뷰를 담아 돌려준다. (ADR-005·018, design/03 §4.2)
**FR-021 이모지 반응** `[층 A]` — When 방문자가 글에 반응하면, the system shall 반응과 outbox 이벤트를 한 트랜잭션에 기록하고 집계를 갱신한다.
**FR-022 수정·삭제** `[층 A]` — Where 작성자가 GitHub 로그인 사용자이면, when 본인 글을 수정·삭제하면, the system shall 반영한다. 익명 글은 수정·삭제할 수 없다.
**FR-023 신고·숨김** `[층 A]` — When 방문자가 글을 신고하면, the system shall 신고를 기록하고, when 관리자가 숨김 처리하면, the system shall 그 글을 공개 목록에서 제외한다.
**FR-024 속도·길이 제한** `[층 A]` — When 요청이 속도 제한 또는 길이 제한을 넘으면, the system shall 거부하고 사유를 반환한다. 길이: 글 500자·10줄, 표시 이름 2~20자, 신고 사유 200자, 반응 6종 고정 이모지. (ADR-023 §2, design/03 §1)
**FR-025 신고 메모 보호** `[층 B]` — When 방문자가 신고에 메모를 첨부하면, the system shall 메모를 필드 암호화(AES-256-GCM)해 저장하고 이벤트·읽기 모델·로그·요청 재생 기록에는 싣지 않는다. (ADR-026, F11 GB-06)
**FR-026 신고 메모 열람** `[층 B]` — When 관리자가 신고 메모를 열람하면, the system shall 복호화해 관리자에게만 보여주고 열람 사실을 감사 로그에 남긴다. (ADR-026·027, F11 GB-27)
**FR-027 쓰기 잠금** `[층 B]` — While 관리자가 쓰기 잠금을 켜 둔 동안, the system shall 글 작성·수정·반응 추가·신고를 503 과 `Retry-After` 로 거절하고 잠금 사유를 보여주되, 삭제·반응 취소·관리자 조치·로그인은 허용한다. (ADR-008·023, design/03 §4.2, GB-10·11)
**FR-028 멱등 쓰기** `[층 A]` — When 클라이언트가 같은 `Idempotency-Key` 로 쓰기 요청을 다시 보내면, the system shall 처음 처리 결과를 재생하고(같은 키·다른 내용은 422, 처리 중은 409), 키 기록은 24시간 뒤 삭제한다. (ADR-014, design/03 §3)

### 이벤트 처리 (outbox)
**FR-030 전달** `[층 A]` — While outbox 에 미처리 이벤트가 있으면, the system shall 폴링 또는 NOTIFY 로 이를 가져와 소비자에게 전달한다.
**FR-031 수신함(inbox)과 멱등 소비** `[층 A]` — When 이벤트가 전달되면, the system shall 수신 모듈의 inbox 에 먼저 저장하고(같은 메시지 id 의 중복은 무시), 저장된 메시지를 선점해 처리하며, 같은 이벤트가 재전달되어도 효과는 한 번만 낸다.
**FR-032 재시도** `[층 A]` — If 소비가 실패하면, the system shall 상한까지 재시도하고 초과분은 격리(dead-letter)하여 시각화·지표에 노출한다.
**FR-033 상태 선점** `[층 A]` — When 여러 처리 주체가 같은 outbox·inbox 항목을 동시에 처리하려 하면, the system shall 조건부 갱신으로 한 주체만 `processing` 상태로 선점하게 하고, 임대 시간이 지난 선점은 회수하며, 회수된 뒤 늦게 도착한 이전 주체의 완료 갱신은 거절한다.
**FR-034 낙관적 버전** `[층 A]` — When 같은 글을 동시에 수정·숨김하면, the system shall `version` 이 맞는 한 건만 반영하고 나머지는 409 와 최신 상태를 반환한다.
**FR-035 읽기/쓰기 분리** `[층 A]` — The system shall 조회를 읽기 모델에서만 수행하고, 읽기 모델은 이벤트 처리로만 갱신하며(보관 정리·재구성의 문서화된 예외 제외), 오래된 순번의 이벤트는 필드별 순번으로 무시한다. (ADR-018, database-schema §5)
**FR-036 읽기 모델 재구성** `[층 B]` — When 운영자가 재구성을 실행하면, the system shall 그림자 테이블로 읽기 모델을 점검 모드 없이 다시 만들고 재구성 중 들어온 쓰기를 반영한 뒤 한 트랜잭션에서 교체한다. (ADR-023 §6, GB-26)
**FR-037 dead 재투입** `[층 B]` — When 운영자가 격리(dead)된 메시지를 재투입하면, the system shall 상태를 되돌리고 시도 횟수를 초기화하며 사유를 감사 로그에 남긴다. (ADR-023 §5, EV-07)
**FR-038 보관 정지** `[층 C]` — While 증거 보존을 위해 보관 정지가 켜져 있으면, the system shall 보관 정리와 로그 삭제를 건너뛰고 24시간 뒤 자동 해제하며 지속 시 경보한다. (ADR-028, EV-16)

### 이벤트 흐름 시각화 (라이브 데모)
**FR-040 내 동작 상세** `[층 A]` — When 방문자가 쓰기 동작을 하면, the system shall 그 이벤트가 작성→outbox→전달→소비를 지나는 단계를 **해당 세션(익명 세션 포함)에게만** `/ws/private` 연결로 실시간 전송해 상세히 표시한다. (ADR-003·014, design/04 §1)
**FR-041 전체 익명 요약** `[층 A]` — The system shall 다른 방문자의 활동을 내용·식별자 없이 흐름과 개수로만 표시한다.

### 실시간 기능 (WebSocket)
**FR-050 실시간 반영** `[층 A]` — When 새 글·반응·집계 변화가 생기면, the system shall 접속 중인 방문자에게 WebSocket 으로 전달한다. 연결은 **public(`/ws/public`, 사이트 최초 진입 시, 인증 없음)** 과 **private(`/ws/private`, 세션 확인 후, 세션 쿠키 필수)** 의 서로 다른 두 개다. (design/04 §1)
**FR-051 재연결·백프레셔** `[층 A]` — If 연결이 끊기면, the system shall 클라이언트가 연결별로 독립해 자동 재연결하고 public 연결은 마지막 순번부터 놓친 변화를 복구(이력 부족 시 스냅샷)하며, private 연결의 놓친 단계는 REST 로 보충한다. 느린 클라이언트는 앱 레벨 송신 큐 상한(64건/256KB) 초과 시 그 연결만 닫아 서버를 막지 않게 한다. (ADR-014·022, design/04 §5·§6)

### 운영 지표 대시보드
**FR-060 지표 수집** `[층 A]` — The system shall 요청 수·지연·에러·outbox 적체·WebSocket 연결 수를 Prometheus 형식으로 노출한다.
**FR-061 공개 임베드** `[층 A]` — The system shall Grafana 를 **읽기 전용 공개 대시보드(Public dashboards)** 로 사이트에 임베드한다. 임베드가 안 되면 익명 Viewer 같은 후퇴안을 쓰지 않고 임베드를 포기해 링크·스크린샷으로 대체한다(익명 Viewer 는 임의 PromQL 실행이 가능함을 로컬 실측 — tech-stack §11.1, ADR-022).
**FR-062 운영 상태 기록** `[층 C]` — The system shall 백업·로그 아카이브·배포 실행 결과를 상태 파일로 기록하고 worker 가 이를 `pf_ops_*` 지표로 노출한다(파일 없음·오래됨·실패를 구분). (ADR-027 후속, F17 OB-15·16)
**FR-063 경보 알림** `[층 C]` — When 경보 규칙이 임계를 넘으면, the system shall Grafana 경보로 Discord 웹훅에 알리고 반복 간격(4시간)과 해소 알림을 지킨다. (F17 OB-17·§17)

### 가용성
**FR-070 정적 폴백** `[층 A]` — If 백엔드가 응답하지 않으면, the system shall 자기소개·아키텍처 페이지를 정적 폴백으로 계속 제공하고 데모 영역에만 '점검 중'을 표시한다.

### 데이터 보관
**FR-080 보관 기간** `[층 A]` — The system shall 방명록 글은 보관하고, 세션·이벤트 로그는 7일 후 자동 삭제한다. 삭제된 글은 본문을 비운 묘비로 남는다. (ADR-008·023, database-schema §9)
**FR-081 백업·복구** `[층 B]` — The system shall 방명록·신원 쓰기 스키마를 매일 백업해(일 7·주 4 보관) 암호화하고, 빈 DB 로 복원하는 복구 시험 절차를 갖는다. (ADR-023 §9, F17 OB-10)

### 서버 기록·감사
**FR-090 감사 기록** `[층 B]` — When 인증·관리자·시스템 행위가 일어나면, the system shall 행위와 **같은 트랜잭션**에서 감사 로그에 추가 전용으로 기록한다(행위가 롤백되면 감사 행도 없다). (ADR-027, EV-14)
**FR-091 감사 조회** `[층 B]` — Where 관리자가 감사 로그를 조회하면, the system shall 키셋 페이지로 제공하고 비관리자는 403 으로 거부한다. (ADR-027, EV-15)
**FR-092 서버 로그 4종** `[층 B]` — The system shall 앱 로그·접근 로그·감사 로그·운영 상태를 구분해 기록하고, 접근 로그에는 IP·쿼리스트링·User-Agent·Referer·쿠키를 남기지 않으며 접근 로그와 앱 로그를 `req_id` 로 연결한다. (ADR-027)
**FR-093 로그 보관** `[층 B]` — The system shall 앱·접근 로그를 일 단위 gzip 아카이브로 7일 보관하고, 감사 로그는 `auth` 7일·`admin`/`system` 90일 뒤 삭제한다. (ADR-027, OB-15, EV-10)

### 데이터 보호
**FR-100 컬럼 보호 등급** `[층 C]` — The system shall 모든 DB 컬럼에 보호 등급(PUB·SYS·PSD·PII·HSH·ENC)을 부여하고, 분류가 없는 컬럼은 CI 에서 실패시킨다. (ADR-026, database-schema §9.1, CM-12)
**FR-101 필드 키 회전** `[층 C]` — When 운영자가 키 회전을 실행하면, the system shall 옛 키로 암호화된 행을 새 키로 멱등하게 재암호화한다. (ADR-026, F16 CLI)
**FR-102 백업 키 분리** `[층 C]` — The system shall 백업 암호화에 수신자 공개키만 서버에 두고 개인키를 서버에 두지 않는다. (ADR-026)

### 보안 운영
**FR-110 비밀 스캔** `[층 C]` — When 비밀로 보이는 문자열이 커밋되면, the system shall CI 와 pre-commit 에서 검출해 병합을 막는다. (ADR-028, CM-13)
**FR-111 사고 대응 절차** `[층 C]` — The system shall 자산별 비밀 회전·증거 보존·비상 스위치 절차를 문서화하고 분기별 회전 리허설로 검증한다. (ADR-028, design/13)

### 검색·공유·안내
**FR-120 검색·공유** `[층 A]` — The system shall 공개 페이지를 검색엔진과 링크 공유에 맞게 제공한다: `robots.txt`, `sitemap.xml`(ko/en 은 `hreflang` 로 짝지음), 페이지별 `canonical`, 로케일별 title·description, 로케일별 OG·Twitter 카드(1200×630 정적 이미지, 외부 서비스 없음). 방명록·흐름·지표 화면은 `noindex, follow`, 관리·로그인·API 경로는 색인 금지, 개발·미리보기 환경은 기본 전체 금지(`SEO_INDEXING`)다. 오류는 올바른 상태 코드(404·403·500)와 `noindex` 안내 화면으로, 백엔드 중단은 503(`Retry-After`) 점검 화면으로 보여준다. (design/14 §1~§5)
**FR-121 개인정보·쿠키 안내** `[층 A]` — When 방문자가 개인정보 안내 페이지(`/privacy`)를 열면, the system shall 수집 항목(세션 쿠키, GitHub 공개 프로필 id·login, 작성 글)과 수집하지 않는 항목(접속 IP, 이메일), 보관 기간(글 보관·세션 및 로그 7일·감사 90일), 삭제 요청 문의처(사이트 변수, 미설정이면 자리표시)를 선택된 언어로 표시한다. 쿠키는 필수 쿠키뿐이므로 동의 배너는 기본 비표시이고 변수로 켤 수 있다. (design/12 §4, ADR-008)

## Non-Functional Requirements

### Performance
- API 응답 p95 ≤ 300ms
- 첫 화면 LCP ≤ 2.5초
- 동시 접속 50 을 처리한다
- 측정 방법을 인수 단계에서 고정한다(부하 도구·측정 지점·터널 경유 여부)

### Security
- 인증: 익명 세션 + GitHub OAuth. 영구 쓰기는 로그인 사용자만
- 인가: 관리자는 본인 GitHub ID 허용목록 1명
- 입력: 모든 공개 입력은 길이·속도 제한, 출력은 이스케이프(XSS 방지)
- 비밀값(OAuth 시크릿 등)은 저장소에 두지 않는다
- Grafana 는 읽기 전용 공개(**Public dashboards 만, 후퇴안 없음**), 편집·탐색·데이터소스 접근 불가
- 개인정보 최소 보관: **접속 IP 는 저장하지 않는다**(속도 제한은 nginx 메모리), 세션은 7일 후 삭제·익명화 (ADR-008·023)
- 데이터 보호: 세션 토큰은 해시(SHA-256)로만 저장, 쿠키 서명(HMAC), 신고 메모는 필드 암호화(AES-256-GCM, 키 ID·AAD·회전), 백업은 `age` 공개키로 암호화하며 개인키는 서버에 두지 않는다 (ADR-026)
- 접근 로그·앱 로그·감사 로그에 본문·IP·토큰·쿠키·쿼리스트링을 남기지 않는다(마스킹은 2차선) (ADR-027)
- 보안사고: 비밀 유출 시 증거 보존 → 격리 → 회전 순서로 대응하고 자산별 런북을 둔다 (ADR-028)
- CSRF: `SameSite=Lax` + `Origin` 검사 + JSON 전용 + `Idempotency-Key` 필수의 조합(별도 토큰 없음) (design/10 §3.3)

### Scalability / 자원
- 무료 자원(집 PC 또는 Oracle Always Free Arm)에서 컨테이너 합계가 들어가야 한다. **Always Free Arm 은 최대 4 OCPU/24GB 로 알려져 있으나 설계는 보수적으로 2 OCPU/12GB 만 가정한다(한도는 공식 문서로 재확인 필요 — 미확인, A-029).** 대상: Postgres · API · ws-gateway · worker · Next.js · nginx · cloudflared · Prometheus · Grafana. 연결 수는 탭당 소켓 2개(public·private)로 센다
- 같은 Docker Compose 가 두 호스팅에서 동작한다(호스트별 차이는 오버라이드 파일로 한정)

### Consistency / Integrity
- **모든 쓰기(INSERT·UPDATE·DELETE)는 트랜잭션 안에서 실행한다.** 한 문장짜리 쓰기도 예외가 아니며, 읽기 전용 핸들에는 쓰기 메서드가 없다. 대량 삭제·집계는 배치마다 짧은 트랜잭션 (ADR-025·021)
- 쿼리 계층은 Drizzle 빌더 기본, 손으로 쓴 SQL 은 `adapter/postgres/raw/` 에 사유·측정 근거와 함께 등록한다 (ADR-025)

### Operability
- 배포: GitHub Actions 가 이미지를 GHCR 에 빌드하고 호스트가 pull 한다
- 관측: 자기 지표를 Grafana 로 공개한다(FR-061)
- 예약 작업(로그 아카이브·백업·pull 배포)은 systemd 타이머로 돌고 결과를 상태 파일로 남긴다(FR-062). 경보는 Discord 웹훅으로 간다(FR-063)
- 무중단: 롤링 배포 중 WebSocket 은 `bye` 후 지터 재접속, 쓰기는 멱등 키로 재시도 안전 (ADR-014)

### Accessibility
- **WCAG 2.2 AA** 를 목표로 한다(design/07 접근성, design/15 §4·접근성 체크리스트). 본문 대비 4.5:1·큰 글자 3:1, 포커스 링 3:1 이상, 정보는 색에만 의존하지 않는다(흐름 단계는 모양 병행)
- 모든 기능(글 작성·반응·언어 전환·로그인·신고)을 **키보드만으로** 쓸 수 있고 포커스 순서가 시각 순서와 같다. 터치 대상은 44×44px 이상을 권장한다(WCAG 2.2 최소 24px)
- 실시간 갱신은 `aria-live="polite"` 로 알리되 과다 알림을 피한다(예: “새 글 N개”)
- `prefers-reduced-motion: reduce` 에서 흐름 시각화·홈 레일 애니메이션은 즉시 완료(단계 목록)로 대체된다
- 검증은 axe-core 자동 검사(위반 0)와 키보드 시험이다(AC-036). 스크린리더·400% 확대·실기기 터치는 자동 검사로 잡히지 않아 **수동 점검 항목이며 아직 하지 않았다**

### 지원 브라우저 (제안, 구체 버전·시험은 미확인)
- 최신 2개 메이저 버전의 Chromium 계열(Chrome·Edge), Firefox, Safari 계열
- 필요 기능: WebSocket, `Intl`, CSS 변수·`prefers-color-scheme`, ES2022 수준. WebSocket 이 막힌 환경에서도 목록 조회·글 작성은 REST 로 동작하고 실시간 갱신만 빠진다(쓰기는 항상 REST)

### 가용성
- **가용성 목표(SLA)는 두지 않는다.** 단일 호스트 무료 환경이고 집 PC 전원·회선에 의존한다. 대신 정적 폴백 2단계(FR-070: nginx, Cloudflare 정적 미러)로 소개·아키텍처 페이지를 계속 제공하고 데모 영역만 ‘점검 중’으로 표시한다. 롤링 배포는 무중단을 지향하지만(ADR-014) 보장하지 않는다

## Acceptance Criteria

### AC-001: 익명 글 작성이 이벤트로 이어진다
Given 로그인하지 않은 방문자
When 길이 제한 이내의 글을 제출한다
Then 글과 outbox 이벤트가 함께 저장되고, 시각화 화면에 작성→outbox→전달→소비 단계가 순서대로 나타난다.

### AC-002: 원자성
Given 글 저장과 outbox 기록 중 하나가 실패하도록 주입한다
When 글을 제출한다
Then 둘 다 저장되지 않는다.

### AC-003: 멱등 소비
Given 같은 이벤트를 두 번 전달하도록 만든다
When 수신과 처리가 일어난다
Then inbox 에는 한 행만 있고 읽기 모델의 집계는 한 번만 증가한다.

### AC-004: 익명 글은 수정할 수 없다
Given 익명 세션이 쓴 글
When 같은 세션이 수정·삭제를 시도한다
Then 403 으로 거부된다.

### AC-005: 로그인 글 수정·삭제
Given GitHub 로그인 사용자의 본인 글
When 수정·삭제한다
Then 반영되고 다른 사용자는 같은 요청에 403 을 받는다.

### AC-006: 숨김
Given 신고된 글
When 허용목록 관리자가 숨김 처리한다
Then 공개 목록에서 사라진다. 허용목록 밖 사용자는 같은 요청에 403 을 받는다.

### AC-007: 속도 제한
Given 한 세션이 제한을 넘는 속도로 글을 보낸다
When 제한을 넘는 요청이 들어온다
Then 429 와 재시도 안내가 반환된다.

### AC-008: 실시간 반영과 복구
Given 방문자 A·B 가 접속해 있다
When A 가 반응을 남긴다
Then B 화면의 집계가 지연 없이 갱신된다. B 의 연결을 끊었다 복구하면 놓친 변화가 반영된다.

### AC-009: 프라이버시
Given 방문자 A 가 쓴 글
When 방문자 B 가 시각화 화면을 본다
Then 글 내용·세션 식별자는 보이지 않고 흐름과 개수만 보인다.

### AC-010: 정적 폴백
Given 백엔드가 중단되었다
When 방문자가 사이트를 연다
Then 자기소개·아키텍처는 보이고 데모 영역만 '점검 중'이다.

### AC-011: 보관
Given 7일이 지난 세션·이벤트 로그와 방명록 글
When 정리 작업이 돈다
Then 로그와 세션은 삭제되고 글은 남는다. 삭제 글은 본문이 비워진 묘비로 남고, 만료 세션이 남긴 작성자·행위자 연결은 끊긴다(익명화).

### AC-012: 지표·임베드
Given 사이트가 동작 중이다
When 대시보드 페이지를 연다
Then 요청·지연·에러·outbox 적체가 Grafana 임베드로 표시되고 편집 UI 는 노출되지 않는다.

### AC-013: 성능
Given 동시 접속 50 의 부하
When 측정한다
Then API p95 ≤ 300ms, 첫 화면 LCP ≤ 2.5초.

### AC-014: 이중 호스팅
Given 같은 Docker Compose 한 벌
When 집 PC 와 Oracle 호스트에서 각각 올린다
Then 두 곳 모두 AC-001, AC-008, AC-010 을 통과한다.

### AC-015: 동시 선점
Given 같은 inbox 항목을 N 개의 처리 주체가 동시에 선점하려 한다
When 동시에 시도한다
Then 정확히 한 주체만 처리하고 효과는 한 번이다. 임대 만료 후 늦게 완료를 시도한 이전 주체의 갱신은 거절된다.

### AC-016: 동시 수정
Given 같은 글에 대한 두 수정 요청이 같은 `version` 으로 동시에 도착한다
When 처리된다
Then 하나는 성공하고 하나는 409 와 최신 상태를 받는다.

### AC-017: 읽기 모델 재구성과 순서
Given 읽기 모델을 비우고, 이벤트를 순서를 뒤섞어 중복 전달한다
When 처리가 끝난다
Then 읽기 모델은 정본에서 계산한 값과 일치한다. 그림자 테이블 재구성 중에도 목록 조회는 끊기지 않고, 재구성 중 들어온 쓰기가 교체 후 결과에 반영된다.

### AC-018: 신고 메모 보호와 열람
Given 방문자가 센티널 문자열을 담은 메모로 글을 신고했다
When `pg_dump`·outbox payload·`request_key.response_body`·앱/접근 로그를 검사하고, 관리자와 비관리자가 `GET /api/admin/reports/{id}/note` 를 호출한다
Then 센티널 평문은 어디에도 없고(DB 에는 `note_enc` 봉투만), 관리자는 복호화된 메모를 받으며 비관리자는 403 을 받고, 관리자 열람은 감사 로그에 `report_note_read` 로 남는다.

### AC-019: 쓰기 잠금
Given 관리자가 쓰기 잠금을 켰다
When 글 작성·수정·반응 추가·신고를 시도하고, 삭제·반응 취소·관리자 숨김을 시도한다
Then 앞의 넷은 503 과 `Retry-After: 60` 과 잠금 사유를 받고 뒤의 셋은 정상 처리된다. 잠금을 풀면 앞의 넷도 정상 처리되고, 변경은 감사 로그에 `write_lock_changed` 로 남는다.

### AC-020: 감사 기록의 원자성
Given 관리자 숨김 처리 도중 감사 기록 직후 실패하도록 주입한다
When 숨김을 요청한다
Then 글 상태·조치 이력·감사 행이 모두 저장되지 않는다. 주입 없이 성공하면 셋이 모두 저장된다.

### AC-021: 접근 로그 프라이버시
Given `/api/auth/github/callback?code=SECRET&state=X` 와 위조 `X-Forwarded-For` 헤더를 단 요청
When 접근 로그와 앱 로그를 검사한다
Then 접근 로그에는 경로(`$uri`)·상태·시간·`rid` 만 있고 쿼리스트링·IP·User-Agent·Referer·쿠키가 없으며, 같은 `rid` 로 앱 로그의 요청 줄을 찾을 수 있다.

### AC-022: 세션 일괄 폐기
Given 로그인 세션과 익명 세션이 있고 각각 private 연결 중이다
When 운영자가 `revoke-sessions --all` 을 실행한다
Then 기존 쿠키의 다음 요청은 새 익명 세션으로 처리되고, private 연결은 `4401` 로 닫히며(세션 캐시 30초 이내), 감사 로그에 `sessions_revoked` 가 대상 수와 함께 한 행 남는다.

### AC-023: 모든 쓰기는 트랜잭션
Given 읽기 전용 핸들, 잡(reaper·세션 갱신·정리·집계)의 쓰기, 대량 삭제
When 읽기 전용 핸들로 쓰기를 시도하고 잡과 정리를 실행한다
Then 쓰기 시도는 컴파일 오류(우회 시 런타임 거절)이고, 잡의 모든 쓰기는 트랜잭션 안에서 일어나며, 대량 삭제는 배치마다 따로 커밋되어 중간에 중단해도 앞 배치가 남는다.

### AC-024: 컬럼 보호 등급
Given 보호 등급이 없는 컬럼을 추가한 마이그레이션
When CI 의 `check:classification` 이 돈다
Then 실패한다. 등급이 `ENC` 인 컬럼에는 `FieldCipher` 를 거치는 쓰기 경로만 존재한다.

### AC-025: 운영 상태 지표와 경보
Given 합성 시계열과 상태 파일(없음·오래됨·`ok=false`)
When `promtool test rules` 와 `StatusFileCollector` 시험을 돌린다
Then `LoginFailedSpike` 는 10분 10건에서 발화하고 9건에서는 발화하지 않으며(카운터는 기동 시 0 으로 선초기화), `OpsJobStale` 은 26시간을 넘기면 발화하고, 세 상태 파일 경우가 서로 구분되어 노출된다. 시험 알림 1건이 Discord 수신 서버(시험용)에 도착한다.

### AC-026: 보관 정지
Given 증거 보존을 위해 `retention:pause` 를 켰다
When 보관 정리 잡과 로그 아카이브가 돈다
Then 삭제가 일어나지 않고, 24시간 뒤 자동 해제되며, 정지가 지속되면 `RetentionPaused` 경보가 난다. 정지·해제는 감사 로그에 남는다.

### AC-027: 비밀 스캔
Given 시험용 비밀 패턴을 담은 커밋
When PR 검사(`secret-scan`) 또는 pre-commit 훅이 돈다
Then 검출되어 실패한다. `.env`·`secrets/`·`incidents/` 는 저장소에 추적되지 않는다.

### AC-028: 백업과 복구
Given 암호화된 일일 백업
When 사용자 보관 개인키로 복호화해 빈 DB 에 복원한다
Then 행 수와 무결성 검사가 통과하고, 서버 어디에도 개인키가 없으며(공개키만), 신고 메모는 필드 키링이 있을 때만 복호화된다.

### AC-029: 감사 조회와 보관
Given `auth`·`admin`·`system` 감사 행이 시간대별로 있다
When 관리자와 비관리자가 `GET /api/admin/audit` 를 조회하고 보관 규칙이 돈다
Then 비관리자는 403, 관리자는 키셋 페이지를 받으며, `auth` 는 7일·`admin`/`system` 은 90일 경계에서 삭제된다.

### AC-030: dead 재투입
Given `dead` 로 격리된 inbox 메시지
When 운영자가 재투입한다
Then 상태가 `received` 로 돌아가 시도 횟수가 초기화되고 처리되며, 사유와 함께 감사 로그에 남는다.

### AC-031: public/private 분리 연결
Given 쿠키가 없는 클라이언트와 익명 세션을 가진 클라이언트
When 각각 `/ws/public`·`/ws/private` 에 연결해 글을 쓴다
Then 쿠키 없는 `/ws/private` 는 업그레이드 단계에서 401 이고 `/ws/public` 은 연결된다. 익명 세션은 private 에서 자기 글의 `flow.step` 을 받고 다른 세션은 받지 못한다. 한 세션의 private 연결이 4개를 넘으면 가장 오래된 연결이 `4409` 로 닫힌다.

### AC-032: 라이선스와 콘텐츠 고지
Given 저장소 루트
When 열어 본다
Then `LICENSE`(MIT)가 있고, README 에 개인 콘텐츠(자기소개·사진·글)는 MIT 범위 밖이며 저작권을 유보한다는 고지가 있다.

### AC-033: 멱등 쓰기
Given 같은 `Idempotency-Key` 로 보낸 글 작성 요청
When 응답을 못 받았다고 가정하고 같은 키로 다시 보낸다(동시 2건 포함)
Then 글은 한 건만 생기고 두 번째는 같은 응답(`Idempotency-Replayed: true`)을 받는다. 같은 키에 다른 본문은 422, 처리 중 재요청은 409 이다.

### AC-034: 필드 키 회전
Given 키 `k1` 로 암호화된 신고 메모들
When `k2` 를 추가해 `active` 로 바꾸고 `rotate-field-keys` 를 실행한다(중간 중단 후 재실행 포함)
Then 모든 행이 `k2` 봉투가 되고 평문은 그대로 복호화되며, 재실행은 변화가 없고, 옛 키 행이 0 이 된 뒤에만 `k1` 을 제거할 수 있다.

### AC-035: 사고 대응 리허설
Given design/13 의 회전·증거 보존 체크리스트
When 분기별 리허설을 실행한다
Then 항목마다 구 비밀이 거부되고 새 비밀로 정상 동작하며 소요 시간이 기록되고, 런북의 수정 사항이 반영된다.

### AC-036: 접근성
Given 주요 화면(홈·자기소개·방명록·흐름·아키텍처·지표·개인정보·관리자 신고·404·점검) × 라이트·다크
When axe-core(`wcag2a`·`wcag2aa`·`wcag21aa`·`wcag22aa`) 자동 검사를 돌리고, 키보드만으로 글 작성·반응 추가·언어 전환을 해 본다
Then 위반이 0건이고 모든 조작이 키보드로 가능하며 포커스 순서가 시각 순서와 같고, 새 글 도착이 `aria-live` 로 한 번 알려지며, `prefers-reduced-motion` 에서는 애니메이션이 없다. (스크린리더·400% 확대·실기기 터치는 수동 점검 항목)

### AC-037: 검색·공유와 오류 화면
Given 배포된 사이트
When `/robots.txt`, `/sitemap.xml`, 각 공개 페이지의 `<head>`, 로케일 안팎의 없는 경로, 비관리자의 `/admin`, 서버 렌더 예외 주입, web 컨테이너 중지를 차례로 시험한다
Then `robots.txt` 가 `/api`·`/ws`·관리자를 막고, sitemap 에 ko/en 이 `hreflang` 으로 짝지어지며, 공개 페이지마다 `canonical`·로케일별 title/description·1200×630 OG 이미지가 있고, 방명록·흐름·지표 화면은 `noindex, follow` 이며, 오류 화면은 404·403·500 상태 코드와 `noindex` 를 갖고, web 중지 시 503 + `Retry-After` 의 점검 화면(`X-Fallback: 1`)이 나온다. 개발·미리보기 환경은 전체 색인 금지다.

### AC-038: 개인정보·쿠키 안내
Given 사이트 변수 일부(문의처 등)를 비운 빌드
When `/ko/privacy` 와 `/en/privacy` 를 연다
Then 수집·미수집 항목, 보관 기간, 쿠키 목록(필수 쿠키뿐), 문의처가 표시되고 미설정 변수는 자리표시이며 동의 배너는 기본 비표시다. 릴리스 빌드(`CONTENT_STRICT=1`)는 필수 변수가 비어 있으면 실패한다.

## Error Handling

| Error Condition | HTTP Code | User Message (ko / en) |
|---|---|---|
| 입력 길이·형식 오류 | 400 | "입력을 확인해 주세요" / "Please check your input" |
| 로그인 필요 | 401 | "로그인이 필요합니다" / "Please sign in" |
| 권한 없음(익명 수정, 비관리자 숨김) | 403 | "권한이 없습니다" / "You don't have permission" |
| 글 없음·숨김 | 404 | "찾을 수 없습니다" / "Not found" |
| 중복(같은 반응 재요청) | 200 | 멱등 — 오류가 아니며 같은 결과를 돌려준다(이벤트 없음) |
| 낙관적 버전 충돌·처리 중 재요청 | 409 | "다른 변경이 먼저 반영되었습니다" / "Another change was applied first" (`version_conflict`·`request_in_progress`) |
| 같은 멱등 키에 다른 내용 | 422 | "같은 요청 키로 다른 내용을 보낼 수 없습니다" / "Request key reused with different content" |
| 쓰기 잠금 중 | 503 | 잠금 사유 표시 + `Retry-After` (`write_locked`) |
| GitHub 로그인 상류 오류 | 502 | "로그인을 완료하지 못했습니다" / "Could not complete sign-in" (`github_unavailable`·`github_rejected`) |
| 속도 제한 | 429 | "잠시 후 다시 시도해 주세요" / "Please retry shortly" |
| 백엔드 중단 | 502/503 | 데모 영역 "점검 중" / "Under maintenance" |
| WebSocket 끊김 | — | 자동 재연결, 상태 표시 |
| 이벤트 소비 반복 실패 | — | dead-letter 로 격리, 시각화·지표에 노출 |

## 확정 체크리스트
명세 확정은 **사용자만** 할 수 있다. 아래를 훑어 본 뒤 “확정”(또는 수정 요청)을 알려 달라. 이 문서는 확정 표시를 하지 않는다.

**수량**: 기능 요구 FR 48개(기존 26 + 역반영 20 + 이번 보강 2), 인수 기준 AC 38개(기존 17 + 역반영 18 + 이번 보강 3), 가정 A-001~A-032(신규 A-018~A-032 포함). 출시 층별 FR: A 29개 · B 10개 · C 9개. NFR 은 접근성·지원 브라우저·가용성 3개 절을 추가했다.

**설계에서 도출되어 사용자 확인이 필요한 FR**: FR-013·025~028·036~038·062~063·081·090~093·100~102·110~111·120~121 — 모두 이미 ADR/설계에 근거가 있고, 이 명세로 옮겨 검증 가능하게(AC-018~035) 만든 것이다. 범위가 과하다고 판단되면 이 목록에서 빼면 된다.

**아직 미확인인 가정**: A-009(정식 Named Tunnel — 임시 터널은 로컬 통과), A-013(Node 22 직접 비교 미실행 — Bun 실행은 로컬 통과·조건부), A-014(nginx TLS 자동화, G7 ③), A-015(Bun WS 수 시간 소크, G2 — 22분 소크는 통과), A-020(경보 임계값 추정), A-022(실제 Discord 전송), A-023(비밀 스캔·`age` 도구 — 로컬 시험은 통과), A-024·025(호스트 systemd·권한), A-027(법적 통지), A-029(Oracle 자원 한도), A-031(지원 브라우저 구체 버전·접근성 수동 점검). 속도 제한 수치는 A-011 갱신 예정.

**내가 사용자 답변 없이 정한 것 (확인 필요)**
