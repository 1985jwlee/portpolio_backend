# Feature: 백엔드 역량 증명형 포트폴리오 사이트

> **위치**: 이 명세는 `README.md` 로드맵의 **Phase 0 과 Phase 1 사이 첫 마일스톤(M1)** 이다. 바둑·KataGo·타임딜·결제는 이 명세의 범위 밖이며 로드맵의 후속 Phase 가 맡는다. (초기 로드맵 문서는 요지를 README·ADR 에 흡수한 뒤 삭제했다.) 결정의 근거는 `docs/adr/` 이다(특히 ADR-002·003·006·013).
> **상태**: 사용자가 “확정”을 명시하지는 않았고 ADR 작성 단계로 넘어갔다. 수정 요청은 언제든 반영한다.

## Overview
채용 담당자·방문자에게 공개되는 포트폴리오 사이트이며, **사이트 자체가 백엔드 작품**이다. 자기소개·아키텍처 설명과 함께, 방문자가 직접 써보는 라이브 데모 3종(이벤트 흐름 시각화 · 실시간 기능 · 운영 지표 대시보드)으로, 그 소재는 방명록+이모지 반응이다. 이를 통해 outbox 기반 이벤트 처리·실시간 전달·관측성 역량을 동작으로 증명한다. 백엔드와 프론트엔드를 함께 설계하며 웹 전용이다. **완전 무료(0원·카드 청구 위험 최소) 자체 호스팅**이 제약이다.

## 확정된 의도 (요약)
| 항목 | 결정 |
|---|---|
| 독자 | 채용 담당자·방문자(공개) |
| 성격 | 이 사이트 자체가 백엔드 작품. **외부 프로젝트(다른 저장소)는 구현 과정에서 참고하지 않는다.** 에이전트 파이프라인은 공개하지 않는다 |
| 플랫폼 | 웹 전용, 한국어+영어 |
| 스택 | 전체 표는 [tech-stack.md](../docs/domains/tech-stack.md). 백엔드 TypeScript(Bun + Elysia), 프론트엔드 Next.js(App Router), DB PostgreSQL 18 + Drizzle |
| 이벤트 | Postgres outbox + 브로커 없이 직접 폴링/NOTIFY |
| 지표 | Prometheus + Grafana 임베드 |
| 호스팅 | 별도 개인 도메인, Docker Compose 한 벌이 집 PC(+Cloudflare Tunnel)와 Oracle Always Free 양쪽에서 뜨는 구조. 1차는 집 PC |
| 1차 출시 | 전부 한 번에 |

## Functional Requirements

### 사이트 콘텐츠
**FR-001 자기소개** — When 방문자가 자기소개 페이지를 열면, the system shall 경력·연락처를 선택된 언어(ko/en)로 표시한다.
**FR-002 아키텍처 설명** — When 방문자가 아키텍처 페이지를 열면, the system shall 이 사이트의 구성(outbox 흐름, 스택 선택 이유, 호스팅 구조)을 선택된 언어로 설명하고 각 데모로 연결한다.
**FR-003 저장소 링크·CI 배지** — The system shall 공개 GitHub 저장소 링크와 CI 상태 배지를 표시한다.
**FR-004 언어 전환** — When 방문자가 언어를 바꾸면, the system shall 모든 화면 문자열을 ko/en 으로 전환하고 선택을 유지한다.

### 방문자 신원
**FR-010 익명 세션** — When 방문자가 처음 접속하면, the system shall 로그인 없이 익명 세션을 발급하고 세션별로 데이터를 격리한다.
**FR-011 GitHub 로그인** — When 방문자가 GitHub 로그인을 하면, the system shall 영구 신원과 표시 이름을 부여하고 이후 쓰기를 그 신원에 귀속한다.
**FR-012 관리자** — Where 로그인한 GitHub ID 가 허용목록(1명)에 있으면, the system shall 숨김 처리 등 관리 권한을 부여한다.

### 방명록 + 반응 (데모 도메인)
**FR-020 글 작성** — When 방문자가 길이 제한 이내의 글을 제출하면, the system shall 글과 outbox 이벤트를 **한 트랜잭션**에 기록한다.
**FR-021 이모지 반응** — When 방문자가 글에 반응하면, the system shall 반응과 outbox 이벤트를 한 트랜잭션에 기록하고 집계를 갱신한다.
**FR-022 수정·삭제** — Where 작성자가 GitHub 로그인 사용자이면, when 본인 글을 수정·삭제하면, the system shall 반영한다. 익명 글은 수정·삭제할 수 없다.
**FR-023 신고·숨김** — When 방문자가 글을 신고하면, the system shall 신고를 기록하고, when 관리자가 숨김 처리하면, the system shall 그 글을 공개 목록에서 제외한다.
**FR-024 속도·길이 제한** — When 요청이 속도 제한 또는 길이 제한을 넘으면, the system shall 거부하고 사유를 반환한다.

### 이벤트 처리 (outbox)
**FR-030 전달** — While outbox 에 미처리 이벤트가 있으면, the system shall 폴링 또는 NOTIFY 로 이를 가져와 소비자에게 전달한다.
**FR-031 수신함(inbox)과 멱등 소비** — When 이벤트가 전달되면, the system shall 수신 모듈의 inbox 에 먼저 저장하고(같은 메시지 id 의 중복은 무시), 저장된 메시지를 선점해 처리하며, 같은 이벤트가 재전달되어도 효과는 한 번만 낸다.
**FR-032 재시도** — If 소비가 실패하면, the system shall 상한까지 재시도하고 초과분은 격리(dead-letter)하여 시각화·지표에 노출한다.
**FR-033 상태 선점** — When 여러 처리 주체가 같은 outbox·inbox 항목을 동시에 처리하려 하면, the system shall 조건부 갱신으로 한 주체만 `processing` 상태로 선점하게 하고, 임대 시간이 지난 선점은 회수하며, 회수된 뒤 늦게 도착한 이전 주체의 완료 갱신은 거절한다.
**FR-034 낙관적 버전** — When 같은 글을 동시에 수정·숨김하면, the system shall `version` 이 맞는 한 건만 반영하고 나머지는 409 와 최신 상태를 반환한다.
**FR-035 읽기/쓰기 분리** — The system shall 조회를 읽기 모델에서만 수행하고, 읽기 모델은 이벤트 처리로만 갱신하며, 오래된 순번의 이벤트는 무시한다.

### 이벤트 흐름 시각화 (라이브 데모)
**FR-040 내 동작 상세** — When 방문자가 쓰기 동작을 하면, the system shall 그 이벤트가 작성→outbox→전달→소비를 지나는 단계를 해당 방문자 화면에 실시간으로 상세히 표시한다.
**FR-041 전체 익명 요약** — The system shall 다른 방문자의 활동을 내용·식별자 없이 흐름과 개수로만 표시한다.

### 실시간 기능 (WebSocket)
**FR-050 실시간 반영** — When 새 글·반응·집계 변화가 생기면, the system shall 접속 중인 방문자에게 WebSocket 으로 전달한다.
**FR-051 재연결·백프레셔** — If 연결이 끊기면, the system shall 클라이언트가 자동 재연결하고 놓친 변화를 복구하며, 느린 클라이언트가 서버를 막지 않도록 제한한다.

### 운영 지표 대시보드
**FR-060 지표 수집** — The system shall 요청 수·지연·에러·outbox 적체·WebSocket 연결 수를 Prometheus 형식으로 노출한다.
**FR-061 공개 임베드** — The system shall Grafana 를 **읽기 전용 공개 대시보드(Public dashboards, 불가 시 익명 읽기 전용 뷰)** 로 사이트에 임베드한다.

### 가용성
**FR-070 정적 폴백** — If 백엔드가 응답하지 않으면, the system shall 자기소개·아키텍처 페이지를 정적 폴백으로 계속 제공하고 데모 영역에만 '점검 중'을 표시한다.

### 데이터 보관
**FR-080 보관 기간** — The system shall 방명록 글은 보관하고, 세션·이벤트 로그는 7일 후 자동 삭제한다.

## Non-Functional Requirements

### Performance
- API 응답 p95 ≤ 300ms
- 첫 화면 LCP ≤ 2.5초
- 동시 접속 50 을 처리한다
- 측정 방법을 인수 단계에서 고정한다(부하 도구·측정 지점·터널 경유 여부)

### Security
- 인증: 익명 세션 + GitHub OAuth. 영구 쓰기는 로그인 사용자만
- 인가: 관리자는 본인 GitHub ID 허용목록 1명
- 입력: 모든 공개 입력은 길이·속도 제한, 출력은 이스케이프(XSS 방지)
- 비밀값(OAuth 시크릿 등)은 저장소에 두지 않는다
- Grafana 는 읽기 전용 공개(Public dashboards 우선), 편집·데이터소스 접근 불가
- 개인정보 최소 보관: IP·세션은 7일 후 삭제

### Scalability / 자원
- 무료 자원(집 PC 또는 Oracle Arm 2 OCPU/12GB)에서 컨테이너 합계가 들어가야 한다: Postgres · API · Next.js · Prometheus · Grafana
- 같은 Docker Compose 가 두 호스팅에서 동작한다(호스트별 차이는 오버라이드 파일로 한정)

### Operability
- 배포: GitHub Actions 가 이미지를 GHCR 에 빌드하고 호스트가 pull 한다
- 관측: 자기 지표를 Grafana 로 공개한다(FR-061)

## Acceptance Criteria

### AC-001: 익명 글 작성이 이벤트로 이어진다
Given 로그인하지 않은 방문자
When 길이 제한 이내의 글을 제출한다
Then 글과 outbox 이벤트가 함께 저장되고, 시각화 화면에 작성→outbox→전달→소비 단계가 순서대로 나타난다.

### AC-002: 원자성
Given 글 저장과 outbox 기록 중 하나가 실패하도록 주입한다
When 글을 제출한다
Then 둘 다 저장되지 않는다.

### AC-003: 멱등 소비
Given 같은 이벤트를 두 번 전달하도록 만든다
When 수신과 처리가 일어난다
Then inbox 에는 한 행만 있고 읽기 모델의 집계는 한 번만 증가한다.

### AC-004: 익명 글은 수정할 수 없다
Given 익명 세션이 쓴 글
When 같은 세션이 수정·삭제를 시도한다
Then 403 으로 거부된다.

### AC-005: 로그인 글 수정·삭제
Given GitHub 로그인 사용자의 본인 글
When 수정·삭제한다
Then 반영되고 다른 사용자는 같은 요청에 403 을 받는다.

### AC-006: 숨김
Given 신고된 글
When 허용목록 관리자가 숨김 처리한다
Then 공개 목록에서 사라진다. 허용목록 밖 사용자는 같은 요청에 403 을 받는다.

### AC-007: 속도 제한
Given 한 세션이 제한을 넘는 속도로 글을 보낸다
When 제한을 넘는 요청이 들어온다
Then 429 와 재시도 안내가 반환된다.

### AC-008: 실시간 반영과 복구
Given 방문자 A·B 가 접속해 있다
When A 가 반응을 남긴다
Then B 화면의 집계가 지연 없이 갱신된다. B 의 연결을 끊었다 복구하면 놓친 변화가 반영된다.

### AC-009: 프라이버시
Given 방문자 A 가 쓴 글
When 방문자 B 가 시각화 화면을 본다
Then 글 내용·세션 식별자는 보이지 않고 흐름과 개수만 보인다.

### AC-010: 정적 폴백
Given 백엔드가 중단되었다
When 방문자가 사이트를 연다
Then 자기소개·아키텍처는 보이고 데모 영역만 '점검 중'이다.

### AC-011: 보관
Given 7일이 지난 세션·이벤트 로그와 방명록 글
When 정리 작업이 돈다
Then 로그와 세션은 삭제되고 글은 남는다.

### AC-012: 지표·임베드
Given 사이트가 동작 중이다
When 대시보드 페이지를 연다
Then 요청·지연·에러·outbox 적체가 Grafana 임베드로 표시되고 편집 UI 는 노출되지 않는다.

### AC-013: 성능
Given 동시 접속 50 의 부하
When 측정한다
Then API p95 ≤ 300ms, 첫 화면 LCP ≤ 2.5초.

### AC-014: 이중 호스팅
Given 같은 Docker Compose 한 벌
When 집 PC 와 Oracle 호스트에서 각각 올린다
Then 두 곳 모두 AC-001, AC-008, AC-010 을 통과한다.

### AC-015: 동시 선점
Given 같은 inbox 항목을 N 개의 처리 주체가 동시에 선점하려 한다
When 동시에 시도한다
Then 정확히 한 주체만 처리하고 효과는 한 번이다. 임대 만료 후 늦게 완료를 시도한 이전 주체의 갱신은 거절된다.

### AC-016: 동시 수정
Given 같은 글에 대한 두 수정 요청이 같은 `version` 으로 동시에 도착한다
When 처리된다
Then 하나는 성공하고 하나는 409 와 최신 상태를 받는다.

### AC-017: 읽기 모델 재구성과 순서
Given 읽기 모델을 비우고, 이벤트를 순서를 뒤섞어 중복 전달한다
When 처리가 끝난다
Then 읽기 모델은 정본에서 계산한 값과 일치한다.

## Error Handling

| Error Condition | HTTP Code | User Message (ko / en) |
|---|---|---|
| 입력 길이·형식 오류 | 400 | "입력을 확인해 주세요" / "Please check your input" |
| 로그인 필요 | 401 | "로그인이 필요합니다" / "Please sign in" |
| 권한 없음(익명 수정, 비관리자 숨김) | 403 | "권한이 없습니다" / "You don't have permission" |
| 글 없음·숨김 | 404 | "찾을 수 없습니다" / "Not found" |
| 중복(같은 반응 재요청) | 409 | "이미 처리되었습니다" / "Already done" |
| 속도 제한 | 429 | "잠시 후 다시 시도해 주세요" / "Please retry shortly" |
| 백엔드 중단 | 502/503 | 데모 영역 "점검 중" / "Under maintenance" |
| WebSocket 끊김 | — | 자동 재연결, 상태 표시 |
| 이벤트 소비 반복 실패 | — | dead-letter 로 격리, 시각화·지표에 노출 |

## Out of Scope
- 에이전트 파이프라인 시연(공개하지 않음)
- 모바일 앱

- 메시지 브로커 — **M1 한정.** 이후 Redis Streams 또는 Kafka 도입은 ADR-006(Proposed)에서 Phase 2 전에 측정 후 결정한다

- 자동 스팸 점수 필터, 사전 승인 방식
- 다중 관리자 · 역할 체계
