# 설계 → 구현 → 검증 추적표

이 저장소는 **모든 것을 먼저 설계한 뒤 AI 를 이용해 구현한다**는 방식을 증명한다. 이 표는 그 사슬이 끊기지 않았음을 보여 준다: 명세의 인수 기준(AC) → 구현 작업(S단계, [구현 계획](design/11-implementation-plan.md)) → 시험 → 코드 위치.

- **갱신 시점:** 구현 작업 한 건이 끝날 때마다 해당 AC 행의 `시험`·`코드`·`상태`를 채운다(작업 진행 절차 §6). 사람이 직접 고치되, 자동 검사(S1-16)가 어긋남을 잡는다.
- **상태:** `미구현` → `구현`(코드 있음) → `검증`(시험이 통과하고 AC 의 Given/When/Then 을 실제로 재현). 시험 없이 `검증`으로 올리지 않는다.
- **시험 칸:** 시험 파일 경로와 시험 이름(`bun test` 출력에 나타나는 이름)을 적는다. 증거 규칙은 [ADR-050](adr/ADR-050-evidence-rule.md).
- **구현 작업 칸**은 구현 계획에서 AC 를 완료 기준으로 언급한 작업을 기계적으로 뽑은 초기값이다(없으면 `—`; 작업이 추가되면 갱신).
- 설계를 고치게 만든 구현 중 발견은 [설계 대비 구현 편차 로그](deviation-log.md)에 남긴다.
