# 코드 해설 — S1-3 `packages/config` (환경변수 스키마·검증·`_FILE`·종료 코드 78)

> 기준 커밋: 이 문서가 추가되는 S1-3 커밋(작성 시점 HEAD 는 `82fb48a`, 변경은 전부 미커밋 작업 트리).
> 블록 해설 7개는 상한(7) 안이다. 리비전이 5개(03·04 각 5회)라 `바뀐 과정에서 배울 것` 절이 있다.

## TL;DR — 이 변경을 한 문장으로

- **앱이 뜰 때 환경변수를 한 번 읽어 타입이 붙은 불변 설정 객체로 만들고, 필수 누락·형식 오류·교차 규칙 위반이면 값 없이 이름만 담은 `ConfigError` 를 돌려주며(종료 코드 78 로 매핑), 비밀은 `SecretString` 에 가둬 어떤 출력 경로로도 평문이 나가지 않게 하는 `@pf/config` 패키지를 새로 만들었다.**
- 부수로 TD-5(`bun test` 가 `.env` 를 자동으로 읽음)를 루트 `bunfig.toml` 의 `env = false` 로 닫았고, TD-6 의 `@pf/*` 행과 TD-7 의 7-3(`workspace:*` 선언 규칙)도 닫았다. 설계 문서와 어긋난 곳은 DV-013·DV-014 로 남겼다.
- **알아 둘 부작용**: 저장소 루트에서 도는 `bun <파일>`·`bun test` 는 이제 `.env` 를 읽지 않는다. `.env` 가 필요한 명령은 `--env-file=.env` 를 직접 붙여야 한다.

## 전체 그림

**이 패키지는 "앱 기동의 첫 단계"다.** 각 앱의 `main.ts`(S1-7 부터)가 `loadConfig(스키마, 원천)` 을 부르고, 성공하면 설정 객체로 나머지를 조립하고, 실패하면 오류를 stderr 에 찍고 `exitCodeFor` 가 돌려준 78 로 끝낸다. 지금은 패키지 밖에 호출부가 0곳이고(`@pf/config` 임포트 0), 첫 소비자는 S1-7 이다. 이 패키지는 **출력도 종료도 하지 않는다** — 경고와 오류를 값으로 돌려줄 뿐이다.

파일은 책임별로 갈려 있다. 한 줄씩:

| 파일 | 책임 |
|---|---|
| `src/sources.ts` | 환경·파일시스템과 닿는 유일한 곳. 순서(`NAME` > `NAME_FILE`)·빈 값·끝 개행·BOM 을 정한다 |
| `src/parse.ts`(비공개) | 문자열 하나를 `int`·`bool`·`url`·`enum`·`csv-int`·`string` 으로 바꾸거나 닫힌 사유 코드를 낸다 |
| `src/schema.ts` | 필드 정의 함수(`field.*`)·`defineSchema`·`mergeSchemas`·타입 추론(`ConfigOf`) |
| `src/loader.ts` | 분류·오류 수집·교차 규칙 실행·`summarize`·`exitCodeFor` |
| `src/secret-string.ts` | 비밀 값 감싸기 |
| `src/schemas/base.ts`·`fields.ts` | 공통 키 `APP_ENV`·`LOG_LEVEL` 과 앱들이 골라 쓰는 공유 필드 정의 |

공개 이름은 17개이고 `index.ts` 가 명시 열거한다(`export *` 없음). 이 해설은 그중 **판단이 들어간 자리·함정·나중에 고칠 자리**만 다룬다. `parse.ts`(관대한 `Number()` 를 피하고 `^-?[0-9]+$` + `isSafeInteger` 로 엄격히 읽음)·`base.ts`·`fields.ts`·`env-example.test.ts`(견본 `.env.example` 키와 스키마 이름의 일치) 는 읽으면 바로 읽혀서 뺐다.

**사용자가 고른 분기**가 코드 모양을 정했다. 0단계에서 종료 코드 78 매핑과 자식 프로세스 시험을 S1-3 에 넣기로 했고(추천과 다름), 계획 단계에서 문서의 `FileBackedEnvSource` 이름을 유지하고 인터페이스를 확장하기로 했다(추천과 다름). 맨 앞 BOM 한 개를 벗기는 것은 계획에 없던 사용자 결정이다. 코드는 전부 AI 작성이다(`Authorship: G`).

## 코드 블록별 해설

### [packages/config/src/secret-string.ts] — `SecretString`

- **목적**: 비밀 값을 들고 다니되 로그·JSON·`console.log`·`util.inspect` 어디로 나가도 `***` 만 나오게 한다. 이 패키지의 존재 이유다.
- **핵심 개념**: TypeScript 의 `private` 은 컴파일 때만 숨긴다. 런타임에는 그냥 속성이라 `{...obj}`·`Object.keys`·`structuredClone` 에 잡힌다. 반면 `#value`(ECMAScript 비공개 필드)는 언어 자체가 밖에서 못 보게 막는다.
- **한 줄 해설**:
  - `secret-string.ts:9` `readonly #value` — 값이 프로퍼티가 아니라서 전개·열거에 안 나온다. `:13` `Object.freeze(this)` 로 인스턴스도 못 바꾼다.
  - `:20-27` `toString`·`toJSON` 이 `***`. 문자열 보간·`JSON.stringify` 경로를 막는다.
  - `:29` `[Symbol.for("nodejs.util.inspect.custom")]` — `console.log`·`inspect` 가 객체를 그릴 때 부르는 훅이다. `node:util` 을 임포트하지 않고 전역 심볼을 쓴다. Bun 에서 이 둘이 같은 심볼이라는 것은 **코드만으로는 단정할 수 없고** 시험 T3 가 지킨다.
- **의도한 동작**: 값을 꺼내는 길은 `reveal()` 하나뿐이다.
- **수정 포인트**: 새 출력 경로(예: 다른 로거의 직렬화 훅)가 값을 흘리면 `secret-string.test.ts` 에 그 경로로 센티널(`crypto.randomUUID()`)이 안 나오는 단정을 먼저 더하고, 빨강을 본 뒤 이 클래스에 훅을 더한다.
- **엣지케이스/주의**: 센티널을 소스에 리터럴로 쓰지 않는다. 시험이 실패할 때 오류 출력이 소스 줄을 찍으면서 센티널이 새기 때문이다(`secret-string.test.ts:2`). `T3` 의 `toContain("***")` 단정이 없으면 훅이 사라져도 `SecretString {}` 로 나올 뿐 값은 안 새서 시험이 초록으로 남는다 — 구현 중 G3b 가 실제로 처음엔 초록이었고 이 단정을 더해서 잡았다.

### [packages/config/src/sources.ts] — `FileBackedEnvSource` 와 `EnvLookup`

- **목적**: "이 이름의 값이 어디서 왔고 어떤 상태인가"를 값 하나로 돌려준다. Docker secrets 처럼 `DATABASE_URL_FILE=/run/secrets/x` 로 비밀을 파일로 주는 방식을 지원한다.
- **핵심 개념**: 원천(source)은 `lookup(name)` 하나를 가진 객체다. 결과 `EnvLookup` 은 네 갈래 판별 유니온이다 — `absent` · `env`(`bothSet` 포함) · `file`(값) · `file`(`failure`). 문서의 옛 인터페이스 `get(name): string` 은 "파일을 못 읽었다"를 실을 수 없어서 확장했다(DV-013).
- **한 줄 해설**:
  - `:36-40` `fromRaw` — **빈 문자열은 없음이다.** `.env.example` 이 필수 비밀을 빈 채로 두므로 복사만으로 기동이 성공하면 안 된다.
  - `:100-121` `lookup` — `NAME` 이 있으면 그것을 쓰고 **파일은 읽지 않는다**. 둘 다 있으면 `bothSet: true`(로더가 경고를 만든다). `NAME` 이 없고 `NAME_FILE` 만 있으면 읽는다. 읽기 실패는 값이 아니라 `failure` 로 돌려준다 — 기본값으로 빠지면 비밀 마운트가 빠진 기동이 조용히 성공한다.
  - `:66-77` `readSecretFile` — 예외 메시지에 경로가 들어 있어서 버리고 `file_not_found`(ENOENT)·`file_unreadable` 두 코드만 돌려준다.
  - `:81-84` `normalizeSecretText` — 맨 앞 BOM 한 개와 끝의 `\r`·`\n` 연속을 지운다. 공백·탭·중간 개행은 둔다.
- **의도한 동작**: 순서·빈 값·끝 개행은 원천이 정하고, "빈 파일이면 invalid"는 로더가 정한다(원천은 `value: ""` 를 그대로 돌려준다).
- **수정 포인트**: 읽기 규칙(정규화·우선순위)은 이 파일 한 곳이다. 읽기 함수는 생성자 둘째 인자로 주입되므로(`:94`) 시험에서 가짜 파일 시스템을 끼울 수 있다. 값 원천을 하나 더 만들려면 `EnvSource` 를 구현한다.
- **엣지케이스/주의**:
  - `:82` 의 `"﻿"` 은 **눈에 안 보이는 U+FEFF 한 글자**다(바이트 `EF BB BF` 로 확인). 편집기가 이 글자를 지워 `""` 로 만들면 `startsWith("")` 가 항상 참이라 **첫 글자를 매번 잘라 먹는다.** `file-source.test.ts` F1b 가 지킨다.
  - BOM 을 읽기 함수가 아니라 원천에서 지우는 이유: `readFileSync` 는 BOM 을 남기고 `Bun.file().text()` 는 지운다(심부름꾼 실측 E2). 읽기 방법이 바뀌어도 결과가 같게 하려는 것이다.
  - `ProcessEnvSource` 는 공개돼 있어 B9(모듈은 `process.env` 를 직접 읽지 않는다) 를 공개 API 로 우회할 수 있다. 정하는 자리는 S1-7·S2-1 이고 아직 닫지 않았다.

### [packages/config/src/loader.ts] — `loadConfig`·`summarize`·`exitCodeFor`

- **목적**: 스키마의 필드를 한 번 돌아 값을 모으고, 한꺼번에 오류를 보고하고, 마지막에 교차 규칙을 돌린다.
- **핵심 개념**: **오류를 첫 번째에서 멈추지 않고 전부 모은다.** 운영자가 한 번에 누락 목록을 봐야 하기 때문이다. 오류는 `ConfigError.details` 에 `missing`(이름)·`invalid`(이름 + 닫힌 사유 코드)·`violations`(규칙 id)로 담기고 **입력 값은 어디에도 실리지 않는다**(`:116-129`).
- **한 줄 해설**:
  - `:76-101` `loadField` — `lookup` 결과 네 갈래를 `switch` 로 분기. `env` 이고 `bothSet` 이면 경고, `file` 의 `failure` 는 invalid, `file` 의 빈 값은 `file_empty`, `absent` 는 `fallbackFor`.
  - `:58-68` `fallbackFor` — `presence`(required·default·optional)로 갈린다. 값이 `false`·`0` 인 기본값을 "없음"으로 오판하지 않으려고 값이 아니라 `presence` 를 본다.
  - `:163-172` — 필드 오류가 하나라도 있으면 거기서 반환하고, **오류가 없을 때만** 교차 규칙을 돈다. 규칙은 타입이 확정된 값만 받는다.
  - `:192` `summarize` — 값이 `SecretString` 인지(`instanceof`)로 비밀을 가른다. 비밀은 이름만 `secretNames` 에 낸다.
  - `:205-207` `exitCodeFor` — 인자와 무관하게 78(sysexits `EX_CONFIG`). 이 함수는 설정 오류에만 쓴다.
- **의도한 동작**: 반환 `config` 는 `Object.freeze` 된 평면 객체이고 키가 곧 환경변수 이름이다(사용자 결정).
- **수정 포인트**: 새 오류 사유는 `InvalidReason` 에 코드를 더하고 `loadField`(원천 쪽 사유) 또는 `parse.ts`(형식 사유)에서 낸다. 이름 ≠ 값 원칙 때문에 사유 문자열에 입력 일부를 넣지 않는다. 새 경고 종류는 `LoadWarning.code` 를 넓힌다.
- **엣지케이스/주의**:
  - `ConfigError` 에는 message·cause 를 주지 않는다. 메시지는 kernel 이 정한 `config_invalid` 다.
  - 개별 필드는 `Object.entries(schema.fields)` 순서, 즉 선언 순서로 돈다. 오류 목록의 순서도 그것이다.
  - 로드 결과의 타입(`ConfigOf<S>`)은 `loadConfig` 의 공개 오버로드(`:132-138`)가 만들고, 구현 시그니처(`:139`)는 넓은 타입을 쓴다. 단언(`as`)은 쓰지 않았다.

### [packages/config/src/schema.ts] — 타입 운반(`FieldSpec<V, P>`·오버로드)과 `build` 가드

- **목적**: 필드를 `field.int({ default: 30 })` 처럼 정의하면 설정 객체 타입에 `number` 가 자동으로 붙게 하고, `secret` 이면 `SecretString`, `optional` 이면 `V | undefined` 로 추론되게 한다.
- **핵심 개념**: **오버로드(overload)** 는 같은 함수 이름에 여러 호출 모양을 선언하고, 컴파일러가 **위에서부터 처음 맞는 것**을 고르는 문법이다. 마지막 구현 시그니처는 외부에서 보이지 않는다. 이 패키지는 이것으로 `as` 없이 타입을 좁혔다(계획은 단언 한 곳을 예상했는데 0건으로 풀렸다).
- **한 줄 해설**:
  - `:10-17` `FieldSpec<V, P>` — `V` 는 값 타입, `P` 는 presence 리터럴. 런타임 필드 `presence` 만으로는 타입 추론이 안 되므로 `P` 를 타입에도 실었다.
  - `:21-26` `ValueOf` — `P` 가 `"optional"` 이면 `V | undefined`.
  - `:126-139` `url` 의 오버로드 — **`{ secret, optional }` 이 맨 앞**이다. 변수로 넘긴 옵션이 `{ optional }` 오버로드에 먼저 맞으면 `SecretString` 이 `string` 으로 추론된다(`:125` 주석, 시험 "오버로드 순서"가 지킨다). `string`(`:172-196`)도 같다.
  - `:72-83` `build` 의 런타임 가드 — **비밀 + 기본값**은 던지고, **비밀인데 `url`·`string` 이 아닌 종류**(`int` 등)도 던진다. 타입(오버로드)은 *리터럴로 바로 넘긴 옵션*만 막고 변수로 넘기면 통과하기 때문에 런타임에서도 막는다. 가드가 없으면 기본값은 `summarize.values` 에 평문으로 나가고, 문자열이 아닌 비밀은 `SecretString` 으로 안 감싸져 `values` 로 나간다(`loader.ts:51` 은 문자열일 때만 감싼다).
  - `:57-64` `PUBLIC_NAME` — 오류 문구에 `field.csv-int` 같은 내부 kind 가 아니라 공개 이름(`oneOf`·`csvInt`)을 찍는다.
- **수정 포인트**: 새 필드 종류는 ① `FieldKind` ② `PUBLIC_NAME` ③ `parse.ts` 의 `switch`(`:75`) ④ 오버로드 세 가지(필수·default·optional)를 함께 고친다. 하나라도 빠지면 컴파일러가 `Record<FieldKind, string>` 이나 `switch` 에서 알려준다. 비밀로 허용할 종류를 늘리려면 `:78` 조건과 `loader.ts:51` 의 문자열 판정을 함께 본다.
- **엣지케이스/주의**: 오류 문구는 두 갈래(기본값·종류) 모두 시험이 한 문구를 대조한다. 한쪽만 대조하면 다른 쪽을 되돌려도 초록이어서, 처음에는 기본값 쪽 문구를 대조하는 단언이 없었다(m-3).

### [packages/config/src/schema.ts] — `mergeSchemas(a, b, rules?)`

- **목적**: 공통 스키마(`baseSchema`)와 앱별 조각을 합쳐 앱 스키마를 만든다.
- **한 줄 해설**:
  - `:231` 같은 이름이 양쪽에 있으면 **같은 명세 객체(참조 동일)** 일 때만 하나로 합친다. 다르면 `throw` — 설정값 오류가 아니라 프로그래머 오류라서 `Result` 가 아니다. `fields` 객체의 공유 필드를 양쪽이 가져다 쓰면 참조가 같다.
  - `:238` 규칙 순서는 `a` 의 규칙, `b` 의 규칙, 세 번째 인자의 교차 규칙이다.
- **의도한 동작**: 세 번째 인자는 **병합 뒤 두 조각의 키를 함께 읽는 규칙**이다. 샘플 `apiLike` 의 `production_cookie_secure` 는 `base` 의 `APP_ENV` 와 API 조각의 `COOKIE_SECURE` 를 함께 본다(`sample-schemas.ts:43-49`). 어느 한 조각의 규칙은 상대 조각의 키를 읽을 수 없다.
- **수정 포인트**: 서명을 바꾸면 호출부는 지금 픽스처 2곳과 `schema.test.ts` 뿐이다. 문서 정본은 `design/01 §7.1` 이다.
- **엣지케이스/주의**: 이 세 번째 인자는 처음 구현에 없었다. 우회(조각을 만들지 않고 필드 객체를 펼쳐 `defineSchema` 에 한 번에 넣기)는 **`base` 의 규칙을 조용히 버린다.** 사용자가 서명 변경까지 포함해 닫기로 했다(Q11).

### [packages/config/test/boot.test.ts]·[test/fixtures/boot-probe.ts] — 종료 78 경계 시험

- **목적**: "필수 누락이면 78 로 끝나고 비밀은 출력에 없다"를 **실제 자식 프로세스로** 확인한다(L3). `main.ts` 가 아직 없으므로 `boot-probe.ts` 가 `main.ts` 의 S1-3 몫(로드 → 요약 출력 / 실패 시 오류 출력 + 종료 코드)을 흉내 낸다.
- **한 줄 해설**:
  - `boot.test.ts:11-13` `fileURLToPath(new URL(…))` — `URL.pathname` 은 퍼센트 인코딩이라 경로에 공백·한글이 있으면 자식이 파일을 못 찾는다. 처음 구현은 `pathname` 이었고 리뷰가 공백·한글 경로에서 B1~B3 이 전부 빨개지는 것을 재현했다(M-3).
  - `:30-38` 자식은 `[process.execPath, "--no-env-file", probe, sample]` 로 띄우고 **env 에 필요한 변수만** 준다. cwd 는 저장소 밖 임시 디렉토리다. 부모 환경이나 `.env` 가 시험에 섞이지 않는다. `process.execPath` 를 쓰는 이유는 env 를 비우면 PATH 가 없어 문자열 `"bun"` 을 못 찾기 때문이다(사전조사 실측).
  - 센티널(`crypto.randomUUID()`)을 시험 실행 중에 만들어 stdout·stderr 에 없다는 것을 단정한다. B1 은 누락 이름이 stderr 에 *있음* 도 함께 본다.
  - `boot-probe.ts:21-27` 탐침은 **예외를 던지지 않는다.** 처리 안 된 오류 출력은 근처 소스 줄을 그대로 찍어 비밀이 새기 때문이다. 대신 `JSON.stringify(result.error)` 를 stderr 에 쓰고 `process.exitCode` 를 설정한다.
- **수정 포인트**: 샘플을 바꾸면 `sample-schemas.ts` 의 필수 필드와 B1 의 기대 이름이 같이 움직인다. 실제 앱이 생기면(S1-7) 이 시험은 **샘플이 아니라 진짜 `main.ts`** 로 다시 세워야 한다(B1~B3 은 샘플 스키마만 지킨다).
- **엣지케이스/주의**: Windows·Linux CI 러너·`bun test --parallel` 에서의 흔들림은 확인하지 못했다(S1-6).

### [bunfig.toml]·[scripts/bunfig-env.test.ts] — TD-5(`.env` 자동 로드 차단)

- **목적**: Bun 은 `.env` 를 자동으로 읽는다. 시험이 개발자 PC 의 `.env` 에 좌우되지 않게 막는다.
- **핵심 개념**: 키 이름과 **자리**가 중요하다. 최상위 `env = false`(`bunfig.toml:4`)는 막고, `[test]` 표 안의 `env = false` 는 여전히 읽는다(사전조사 실측). 그래서 주석이 "이 키는 최상위여야 한다"고 적는다.
- **한 줄 해설**:
  - **대조군 D1**(`bunfig-env.test.ts:50-59`) — bunfig 없는 임시 디렉토리에서는 `.env` 값이 보인다. 이 단정이 깨지면 D2 는 아무것도 증명하지 못한다. 대조군 없이 "안 보인다"만 확인하면 `.env` 를 아예 안 만들어도 초록이 되기 때문이다.
  - **D2**(`:61-72`) — 루트 `bunfig.toml` 을 임시 디렉토리에 복사하면 `PROBE=unset` 이다.
  - `:39-45` 자식 `bun test` 는 `env: {}` 로 부모 환경 없이 돌린다. 임시 디렉토리는 저장소 밖이다(안에 두면 바깥 `bun test` 가 탐침 시험 파일을 함께 집어 간다).
- **수정 포인트**: `bunfig.toml` 에 `[test] preload` 를 넣는 순간(S1-6·S1-10) D2 가 `preload not found` 로 빨개진다. D2 가 파일을 **통째로 복사**하기 때문이다. 그때 D2 를 고친다 — 지우거나 빼지 않는다(`:4` 주석).
- **엣지케이스/주의**:
  - **저장소 전체 부작용**: 루트에서 도는 `bun <파일>` 과 `bun test` 는 `.env` 를 안 읽는다. `--env-file=.env` 는 여전히 읽는다. `.env` 를 읽어야 하는 루트 명령은 S1-4 `db:migrate`, S1-7 `dev`·`db:seed`·`worker <cmd>` 다(`tech-debt.md:140`).
  - `bun run <스크립트>` 는 bunfig 와 무관하게 스크립트 셸에 `.env` 를 넣지 않는다(영향분석 실측). 그래서 CI·현재 루트 스크립트는 영향이 없다.
  - `bunfig.toml` 은 작업 디렉토리 기준이라 **하위 디렉토리에서 `bun test` 를 돌리면 걸리지 않는다.**

## 바뀐 과정에서 배울 것

구현이 다섯 번(최초·r2~r5), 리뷰가 다섯 번 돌았다. 계획은 한 번도 다시 쓰지 않았고 영향분석도 한 번이다.

| 단계 | 지적 | 교정 |
|---|---|---|
| 최초 → r2 (리뷰 r1 🔴) | **M-1**: 비밀의 기본값 금지를 타입(오버로드)으로만 막았다. 변수로 넘긴 옵션이면 비밀이 `summarize.values` 에 평문으로 나간다(재현됨) | `build` 에 런타임 가드. 비문자열 비밀(`field.int({secret})`) 경로도 같은 결함이라 한 조항 더 넣었다 |
| 〃 | **M-2**: 계획 계약표의 `secret + optional` 이 `url`·`string` 에 없었다 | 오버로드를 **맨 앞에** 추가. 순서가 틀리면 `SecretString` 이 `string` 으로 추론된다 |
| 〃 | **M-3**: `boot.test.ts` 가 `URL.pathname` 을 써서 경로에 공백·한글이 있으면 거짓 빨강 | `fileURLToPath` |

**얻을 교훈**
- **타입이 막는 것과 런타임이 막는 것은 다르다.** 타입은 *신선한 리터럴*만 잡는다. 보안 성질(비밀 출력 금지)은 런타임 가드를 하나 더 둔다.
- **가드를 만들면 되돌려서 빨강을 본다.** 구현 중 G3b(검사 훅 삭제)가 처음에 초록이었다. 센티널이 안 나온다는 *부정* 단정만으로는 훅이 있는지 없는지 모른다 — `***` 가 나온다는 *긍정* 단정을 함께 둔다.
- **파일 경로는 `URL.pathname` 이 아니라 `fileURLToPath` 다.** 공백·한글·Windows 에서 갈린다.
- **전역 설정을 바꾸면 인계 대상은 "첫 소비자"가 아니라 "모든 소비자"다.** 영향분석은 같은 문구를 쓰는 세 자리를 모두 찾았다. 사용자가 고른 선택 항목(R5)까지 포함해 닫았다.
- **파일을 통째로 복사하는 시험은 그 파일에 새 키가 생길 때 깨진다.** 결합을 주석에 적어 두었다(R4).

## 더 학습하면 좋은 개념

- **판별 유니온(discriminated union)**: `kind` 로 모양이 갈리는 타입. `EnvLookup`·`FieldOutcome` 이 쓴다.
- **TypeScript 오버로드와 `NoInfer`**: 호출 모양별 반환 타입. `oneOf` 의 `default` 가 값 집합을 넓히지 못하게 한다.
- **ECMAScript `#private` vs TS `private`**: 런타임에 숨기는지 여부.
- **sysexits `EX_CONFIG`(78)**: 설정 오류를 알리는 종료 코드 관례. 감독자(compose 등)가 재시작 여부를 정한다.
- **Docker secrets 의 `_FILE` 관례**: 공식 postgres 이미지는 `NAME` 과 `NAME_FILE` 이 같이 있으면 오류 종료한다. 이 저장소는 `NAME` 우선 + 경고다(16 §7.2). 둘이 다른 규약이라는 사실만 기록한다.
- **대조군이 있는 시험**: "안 보인다"를 증명하려면 "보이는 경우"가 같은 방법으로 보임을 먼저 증명한다(D1·D2).
