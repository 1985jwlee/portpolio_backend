# ADR-001: 모듈러 모놀리스 + 다중 엔트리포인트
- 상태: Accepted
- 날짜: 2026-11-03
- 근거: 원 계획안 모순 #5·#6, Phase 0 / 명세 Overview / 인터뷰 R9-Q2

## 맥락
유저 0명인 포트폴리오에서 마이크로서비스는 "Premature MSA 를 피한다"는 서사와 모순된다. 반면 HTTP API, WebSocket 연결 유지, 백그라운드 처리(이벤트 디스패처·분석 워커)는 **부하 특성·재시작 영향·스케일 방식이 서로 다르다.** 특히 WebSocket 게이트웨이는 배포하면 연결이 끊기므로 api 와 같은 프로세스에 두면 api 배포가 곧 접속 단절이 된다. 원 계획안은 "모놀리스인데 파드가 왜 나뉘는가"가 설명되지 않은 모순으로 지적했다.

## 결정
**단일 코드베이스(모노레포) + 다중 엔트리포인트.** 같은 코드와 같은 이미지에서 시작 명령만 바꿔 세 프로세스를 띄운다.

| 엔트리포인트 | 책임 | 스케일/재시작 특성 |
|---|---|---|
| `api` | HTTP API, 인증, 쓰기 트랜잭션(+ outbox 기록) | 무상태. 자유롭게 늘리고 재시작 |
| `ws-gateway` | WebSocket 연결 유지, 구독·브로드캐스트 | 연결을 쥠. 재시작 시 클라이언트 재접속 필요 (ADR-014) |
| `worker` | outbox 디스패처, 소비자, 정리 작업 (이후 KataGo 분석) | 큐 소비. 처리량 기준으로 늘림 |

## 설계 상세

### 저장소 구조(제안)
```
apps/
  web/            Next.js
  api/            Elysia HTTP 엔트리포인트
  ws-gateway/     Elysia WebSocket 엔트리포인트
  worker/         디스패처·소비자 엔트리포인트
packages/
  protocol/       WebSocket 메시지·이벤트 스키마 (ADR-004)
  db/             스키마·마이그레이션·쿼리
  modules/        모듈별 도메인 코드 (아래)
```

### 모듈(Bounded Context)
| 모듈 | M1 | 이후 |
|---|---|---|
| `identity` | 익명 세션, GitHub OAuth, 관리자 허용목록 | Passkey |
| `guestbook` | 글·반응·신고·숨김 | |
| `events` | outbox, 디스패처, 단계 추적, 흐름 집계 | |
| `realtime` | 구독·브로드캐스트 | 룸·대국 채널 |
| `observability` | 지표 노출 | |
| `game`, `ledger`, `deal`, `payment` | | Phase 1~5 |

### 경계 규칙
- 모듈은 **다른 모듈의 테이블을 직접 읽지 않는다.** 공개 함수(인터페이스) 또는 이벤트로만 소통한다.
- 스키마는 모듈별로 나눈다: 쓰기 `<m>`, 읽기 `<m>_read`(ADR-018). **스키마 간 FK 를 두지 않는다.** FK 는 모듈 간 마이그레이션 순서를 묶어 경계를 무너뜨린다.
- 경계 위반은 임포트 경계 검사로 CI 에서 실패시킨다. 도구는 **dependency-cruiser** 다(ADR-022). 계층 규칙(`domain ↛ service` 등)과 CQRS 규칙(`usecase/query ↛ 쓰기 포트`)을 정규식 규칙으로 쓰고 `error` 수준으로 CI 를 실패시킨다.

## 대안과 기각 이유
- **서비스별 저장소·DB 분리(MSA)**: 배포·마이그레이션·계약 관리 비용이 크고 이 규모에서 증명할 이득이 없다.
- **완전 단일 프로세스**: WebSocket 연결 수명과 워커 부하가 api 와 섞인다. 배포 시 접속 단절 문제를 분리해 보여줄 수 없다.

## 결과
- 얻는 것: 타입·스키마 공유가 쉽다. 엔트리포인트별 배포·스케일 논의가 가능하다. 무료 호스팅의 자원 제약에서 컨테이너 수를 통제할 수 있다.
- 치르는 것: 모듈 경계는 규율로 지켜야 한다. 도구가 없으면 시간이 지나며 무너진다.

## 위험과 완화
| 위험 | 완화 |
|---|---|
| 모듈 경계가 무너져 사실상 거대 모놀리스가 됨 | 임포트 경계 검사를 CI 에 포함, 위반 시 실패 |
| 세 엔트리포인트의 설정이 어긋남 | 설정은 `packages` 의 단일 모듈에서 읽는다 |

## 검증 방법
- CI: 경계 검사 통과.
- 세 엔트리포인트가 같은 이미지로 기동하고 각자 헬스체크에 응답한다.

## 실서비스라면
유저 규모가 작으면 `api` 와 `ws-gateway` 도 한 프로세스로 합친다. 분리는 "WebSocket 재배포 시 세션 복구"를 증명하기 위한 의도적 선택이다.

## 재검토 조건
모듈 간 직접 참조가 반복적으로 경계를 깨거나, 특정 모듈이 별도 언어·팀으로 가야 할 때.

- 모듈 **내부** 구조(domain · service · usecase, CQRS)는 ADR-019·018 이 정한다. 모듈 **사이**의 소통은 이벤트(outbox → inbox, ADR-005·020)가 기본이다.
