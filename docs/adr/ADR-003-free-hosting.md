# ADR-003: 완전 무료 호스팅 — 집 PC 단일 호스트(Oracle 미추진), Tailscale Funnel 노출, 정적 폴백
- 상태: Accepted
- 날짜: 2026-11-03
- 근거: 명세 FR-070, AC-010·014, 가정 A-006~A-009·A-035·A-036 / 인터뷰 R3-Q3, R5-Q1, R7-Q1, R14-Q2 / 호스팅 조사(2026-11-03, 공식 문서 기준), Tailscale Funnel 공식 문서 tailscale.com/kb/1223/funnel (2026-01-20 검증)

## 맥락
**완전 무료(0원, 카드 청구 위험 최소)** 로 상시 공개하길 원한다(도메인은 2026-11-05 에 구입하지 않기로 했다). 백엔드는 Docker 컨테이너(Postgres, 이벤트 처리, WebSocket, 지표)로 구성된다. 또한 방문자의 첫 인상이 곧 평가이므로 **서버가 꺼진 순간에도 핵심 정보는 보여야** 한다.

## 결정
- **갱신(2026-11-05, 사용자 결정): 신용카드가 없어 Oracle Cloud 는 쓰지 않는다.** 라이브는 **집 PC 한 곳에 백엔드(api·ws-gateway·worker)와 Next.js(web)를 모두 배포**하고 **Tailscale Funnel** 로 노출한다. Oracle 은 선택적 후속(현재 미추진, 가정 A-029)이며 오버라이드 파일 구조(ADR-002)로 이식 여지만 남긴다. 집 PC 중단은 사이트 전체 중단(단일 장애점)이고 사용자가 수용한다(A-033).
- **갱신(2026-11-05, 사용자 결정): 도메인을 구입하지 않는다.** 노출 주소는 `https://<호스트>.<tailnet 이름>.ts.net`(주소는 설정값 `PUBLIC_ORIGIN`, 가정 A-035)이다. 이전의 Cloudflare Tunnel·Cloudflare DNS(가정 A-006)·`cloudflared` 는 **폐기**했다.
- **Funnel 구성(제안, 미검증)**: TLS 는 Funnel 이 우리 PC 에서 종료하므로 nginx(`proxy`)는 TLS 없이 평문 로컬 포트(예: 8080)로만 받고, `tailscale funnel` 이 443 에서 그 로컬 포트로 프록시한다. 포트는 443·8443·10000 만 쓸 수 있고 TLS 연결만 된다. 같은 포트에 serve 와 funnel 을 동시에 쓸 수 없다. Grafana 관리 화면은 Funnel 로 노출하지 않고 `tailscale serve` 로 tailnet 내부 전용으로 둔다(공개 대시보드 허용 경로만 `proxy` 를 거친다).
- **클라이언트 IP**: Funnel 이 전달하는 헤더 사양을 문서에서 확인하지 못했다 — **실제 클라이언트 IP 확보 방법 미확인, 관문 G14 에서 실측**. 확인되기 전에는 IP 에 의존하지 않고 속도 제한을 세션/계정 기준으로 먼저 건다. (Cloudflare Tunnel 의 `CF-Connecting-IP` 가정은 폐기.)
- 백엔드가 죽으면 자기소개·아키텍처는 **정적 폴백**으로 계속 제공하고 데모 영역만 '점검 중'을 보인다(FR-070). **서버·Funnel 이 통째로 끊기면** 별도 주소의 정적 대체 페이지로 **수동 전환**한다(FR-122, [design/16](../design/16-outage-fallback-page.md)). 도메인이 없어 Worker 자동 절체(G13)는 불가이고 도메인 확보 시 후속이다.

### 정적 폴백(구현 방식은 미확정, 가정 A-008)
후보: Next.js 가 정적으로 내보낸 자기소개·아키텍처 페이지를 별도 주소의 무료 정적 호스팅에 올려 둔다. 앱이 죽었을 때 같은 주소에서 자동으로 응답하게 하는 방식은 도메인이 없어 쓰지 못하므로, 앱 안(nginx 1단계)의 정적 폴백과 별도 주소의 대체 페이지(아래)로 나눈다. **데모 영역은 폴백 대상이 아니다.**

### 서버 중단 대체 페이지(2026-11-05 추가)
집 PC 단일 호스트이므로 PC·회선·Funnel 중단 시 사이트 전체가 멈춘다. 앱과 **별도 주소**의 순수 HTML/CSS 대체 페이지(ko/en, 쿠키·추적 없음)를 Cloudflare Pages(`*.pages.dev`) 또는 GitHub Pages(후보, 미확정; GitHub Pages 를 쓰면 이 비공개 저장소가 아닌 별도 배포 위치여야 한다)에 두고, README·프로필에 앱 주소와 함께 안내한다. 중단 시 사람이 안내를 갱신하는 **수동 전환(B안)** 을 채택했다. Worker 절체(A안)는 도메인 확보 시 후속, 관문 G13 은 보류. **자동 절체가 없어 중단 중 앱 주소 접속자는 연결 오류를 볼 수 있다(수용).** 전체 설계·비교는 [design/16](../design/16-outage-fallback-page.md).

### 이식성의 원칙
호스트별 차이는 오버라이드 파일로만 둔다(ADR-002). Funnel 설정(`tailscale funnel`)은 집 PC 호스트에만 존재한다(`tailscaled` 는 컨테이너가 아니라 호스트 서비스, 제안). 다른 호스트로의 이전은 선택적 후속이며 현재 시험 대상이 아니다.

## 대안과 기각 이유
표의 '기각' 행 참조. 요지: 무료 24시간 가동이 안 되거나, 카드·도메인 제약이 있거나, Docker·Postgres 설계를 버려야 한다.

## 결과
- 얻는 것: 0원, 카드 불필요(집 PC 경로).
- 치르는 것: 집 PC 가동률이 곧 사이트 가동률이고 **단일 장애점**이다(수용). Oracle 은 카드가 필요해 쓰지 않는다(회수·재고 부족 위험도 있다).

## 위험과 완화
| 위험 | 완화 |
|---|---|
| 🔴 **Funnel 이 WebSocket 을 통과시키는지 문서에 언급이 없다(미검증)** | 관문 G14 ①. 안 되면 SSE 등으로 대체하는 후속 ADR |
| 🔴 **Funnel 대역폭 한도(수치 비공개, 설정 불가)** | G14 ② 체감 측정. 초과 시 이미지·정적 자산 축소, 실시간 페이로드 축소 |
| 🔴 **Funnel 베타 정책 변경** | 재검토 조건에 둔다. 대체 노출 경로는 도메인 확보 후 Cloudflare Tunnel 복귀(오버라이드 파일 교체) |
| 🔴 **클라이언트 IP 미확인으로 IP 기반 속도 제한 약화** | 속도 제한을 세션/계정 기준 우선으로 설계, G14 ③ 에서 IP 확보 여부 실측. IP 를 못 얻으면 `limit_req` 의 주소별 제한은 사실상 전역 한도가 된다 |
| 🔴 **자동 절체 없음(수동 전환)** | README·프로필에 두 주소 병기, 외부 업타임 점검 알림, 런북(design/16 §4.1). 중단 중 앱 주소 접속자의 연결 오류는 수용 |
| 🔴 **집 PC 중단·정전·회선 단절 = 사이트 전체 중단(단일 장애점)** | 별도 주소 정적 대체 페이지(FR-122, 수동 전환), 무정전 재시작 절차(systemd/compose restart 정책), 외부 가용성 점검(서비스는 검증 필요 — 같은 PC 의 Grafana 는 같이 죽는다). 사용자가 수용(A-033) |
| 무료 정책 변경 | 이중 지원 구조 자체가 완화책 |

## 검증 방법
AC-010(백엔드 중단 시 폴백), AC-014(집 PC 단일 호스트에서 핵심 시나리오), AC-039(별도 주소 대체 페이지), 관문 G14(Funnel WebSocket·대역폭·클라이언트 IP 실측).

## 실서비스라면
항상 켜진 관리형 호스트와 헬스체크 기반 장애 조치를 쓴다.

## 재검토 조건
Funnel WS 실측 실패(G14), Funnel 베타 정책·대역폭 한도 변경, 개인 플랜 용도 제한 확인 결과, 집 회선 가동률 불만족, 무료 정책 변경, 도메인 확보(→ Cloudflare Tunnel·Worker 절체 재검토), 신용카드 확보로 Oracle 등 추가 호스트를 쓰게 될 때.

## 관련 ADR
ADR-002, ADR-014
