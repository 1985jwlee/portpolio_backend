# ADR-052: 추출 가능한 모놀리스 — 계약 패키지·버전 정책·추출 게이트
- 상태: **Proposed** (2026-11-11) — 사용자 결정 항목은 아래 ‘사용자 결정 대기’ 에 분리했다. 승인 전까지 01·11 문서와 경계 검사 규칙은 바꾸지 않는다.
- 날짜: 2026-11-11
- 근거: 사용자 요청(2026-11-11) — “언제든 MSA 로 전환이 가능한 모놀리스가 가장 중요하다. 공용 모듈은 별개 폴더로 관리하고 버저닝도 필요하다.” · ADR-001(모듈러 모놀리스) · ADR-030(서비스 분리 기준) · ADR-043(사가·보상) · ADR-050(증거 규칙)
- 관련 문서: [design/01](../design/01-repository-structure.md) §1·B4·B7 · [design/05](../design/05-event-catalog.md) · [phases/00](../design/phases/00-platform-evolution.md) §2.4(B12)

## 맥락
ADR-001·030 은 MSA 를 쓰지 않는다고 했다. 그러나 사용자의 모토는 **“MSA 로 쓰는 것이 아니라, 필요할 때 떼어 낼 수 있게 만든다”** 이고 이것이 이 프로젝트에서 가장 중요한 품질이다. 현재 설계는 그 모토를 일부만 담는다.

| 이미 있는 것 | 비어 있거나 위험한 것 |
|---|---|
| `packages/` 공용 분리(kernel·protocol·db·infra·config·testkit), B7(packages ↛ modules/apps), B4(모듈 밖은 `@pf/<m>` 의 `index` 만) | **버전이 없다** — 모든 패키지가 항상 최신끼리 묶여, 떼어 낼 때 ‘어느 버전의 계약을 쓰는가’ 가 정의돼 있지 않다 |
| 이벤트 봉투 `schemaVersion`(design/05) | `@pf/protocol` 하나에 전 모듈의 REST·WS·이벤트 스키마가 있어 모듈 하나를 떼면 전체를 끌고 간다 |
| 모듈 간 FK 금지, 타 모듈 표 직접 읽기 금지 | `packages/db` 가 모든 모듈의 `./schema` 를 모아 마이그레이션을 집계한다(모듈이 마이그레이션을 소유하지 않는다) |
| dependency-cruiser 경계 검사 | **모듈이 단독으로 빌드·실행되는지는 검사하지 않는다** — 모토가 증명되지 않는다 |
| | `realtime`·`worker` 가 `identity` 공개 usecase(`ResolveSession` 등)를 직접 호출한다(architecture §2) |
| | 일부 모듈 쌍이 같은 트랜잭션에서 `InTx` 를 부른다(B12 허용 쌍) — 추출하면 깨지는 결합 |

## 결정 (제안)
1. **계약은 모듈의 공개 표면이고 별도 패키지다.** 모듈마다 `@pf/<m>-contract`(이벤트 스키마·DTO·공개 usecase 포트·오류 코드)를 둔다. **다른 모듈과 엔트리포인트는 상대 모듈의 구현이 아니라 계약만 의존한다.** (B4 를 ‘index 만’ 에서 ‘계약만’ 으로 강화)
2. **`@pf/protocol` 은 공용 봉투·상수·전송 규약만 남기고**, 모듈별 이벤트·DTO 는 각 계약 패키지로 옮긴다.
3. **버전은 경계에서만 붙인다.** 대상은 ⓐ 모듈 계약 패키지 ⓑ `kernel`(아무것도 임포트하지 않는 가장 안정된 층). 구현 내부·`infra`·`testkit` 에는 붙이지 않는다(비용 대비 이득 없음).
   - 계약 변경은 하위 호환이면 minor, 깨면 major. 이벤트는 `schemaVersion` 을 올리고 **구버전 소비자를 위한 업캐스트 또는 병행 발행 기간**을 둔다.
   - CI: 골든 JSON(`packages/protocol/golden` 방식을 계약 패키지로 확장) 변경 시 **버전 상승이 없으면 실패**한다.
4. **인증 경계는 `ActorContext` 값으로 푼다.** 모듈은 `identity` 를 호출하지 않고 엔트리포인트(api·ws-gateway·worker)가 세션 쿠키를 `ActorContext`(행위자·역할)로 풀어 주입한다. 모듈을 서비스로 뗄 때는 엣지가 `ActorContext` 를 **짧은 수명(분 단위)의 서명 토큰으로 직렬화**하고 받는 쪽이 복원하는 어댑터만 추가한다. **브라우저 쪽은 계속 불투명 세션 쿠키**(06-auth, 즉시 폐기·세션 고정 방지·DB 유출 시 무효). JWT 는 내부 구간의 직렬화 형식일 뿐 도입 시점은 실제 분리 때다.
5. **추출 가능성을 게이트로 만든다.** 모듈마다 ⓐ 선언한 의존(계약·kernel)만으로 타입체크·빌드되는지 ⓑ 단독 엔트리로 번들되는지를 CI 에서 확인한다. 증거로 **한 모듈(후보: guestbook)을 별도 프로세스로 띄우는 스파이크**를 남긴다(ADR-050).
6. **한계를 문서에 적는다.** `InTx` 쌍(예: order→deal `ConfirmStockInTx`, order→ledger `PostJournalInTx`, support→chat)은 사가(ADR-043)로 바꾸기 전까지 ‘언제든 추출 가능’ 이 성립하지 않는다. 추출 가능성은 **모듈 쌍 단위로 표기**한다(가능 / 사가 전환 필요 / 불가).

## 사용자 결정 대기
| # | 결정 | 권장 | 왜 사용자 몫인가 |
|---|---|---|---|
| 1 | 모토의 엄격도: **직접 의존 0**(이벤트·엔트리포인트 주입만) vs **공개 계약을 통한 의존만 허용** | 후자(현재 문서) | 전자는 `InTx` 쌍 재설계를 포함해 범위가 크게 커진다 |
| 2 | **모듈별 마이그레이션 소유**를 이번에 정할지 | 방향만 정하고 구현 단계 0 에서 결정 | G10 시험·ADR-022(Drizzle 정본)와 맞물린다 |
| 3 | 버전 도구: changesets vs 수작업 + CI 검사 | 수작업 + CI 검사 | 도구 도입은 의존성 추가 |

## 대안과 기각 이유
- **전 패키지 semver**: 내부 변경마다 버전 부담, 소비자가 같은 저장소라 이득 없음 → 경계에서만.
- **지금 MSA 로 시작**: ADR-001·030 의 기각 사유가 그대로다(자원·계약 비용). 이 ADR 은 그 결정을 뒤집지 않는다.
- **세션 대신 JWT 로 통일**: 즉시 폐기 불가·키 하나가 전체 위조 권한·브라우저 저장 위험. 분리 시점의 내부 구간에만 쓴다.

## 결과 (얻는 것 / 치르는 것)
- 얻는 것: 떼어 내기 비용이 구조에 미리 반영되고, 모토가 CI 로 검증된다.
- 치르는 것: 구현 초기에 계약 패키지·버전 검사 작업이 늘고, 모듈 수(M1 5개 → 이후 10개+)만큼 패키지가 늘어난다.

## 위험과 완화
| 위험 | 완화 |
|---|---|
| 계약 패키지가 형식만 남고 구현 모듈로 새는 임포트 | dependency-cruiser 규칙으로 ‘계약만’ 강제(규칙 파일 작성은 구현 단계 0) |
| 버전 규율이 작업 비용 때문에 무너짐 | 변경 감지를 골든 JSON 비교로 자동화 |
| `InTx` 쌍을 숨기고 ‘추출 가능’ 이라고 주장 | 결정 6 의 쌍 단위 표기를 문서에 강제 |

## 검증 방법
- 추출 게이트(결정 5)의 CI 통과와 guestbook 분리 스파이크의 원시 결과·환경·커밋 해시.
- **성공 기준**: 선택한 한 모듈이 계약 패키지와 kernel 만으로 단독 빌드·기동하고 기존 통합 시험을 통과한다. **재검토 조건**: 계약 패키지 관리 비용이 모듈 추가 시간을 눈에 띄게 늘리면(구현 단계 1 에서 사람이 측정) 결정 1·3 을 다시 본다.

## 실서비스라면
서비스 간 호출 계약(gRPC 채택 여부, 미정)과 서비스 인증(mTLS 등 서비스 자격증명)을 함께 정한다. 그때 결정 4 의 서명 토큰 형식과 키 회전을 확정한다.

## 재검토 조건
- ADR-030 의 5축 중 둘 이상이 강하게 해당하는 모듈이 생겼을 때(실제 분리 착수).
- 사용자 결정 1 이 ‘직접 의존 0’ 으로 바뀔 때.
