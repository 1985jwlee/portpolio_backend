# ADR-012: 바둑 룰은 라이브러리로 쓰고 선정은 Phase 1 에서 한다
- 상태: Proposed
- 날짜: 2026-11-03
- 근거: 원 계획안 Phase 1-A, Part 3 확정 사항

## 맥락
룰 엔진(착수 검증, 패(ko), 자충수, 사석 제거, 계가) 직접 구현은 비용과 버그 위험이 크다. 원 계획안은 **라이브러리 활용으로 확정**했고 후보로 `tenuki`, `@sabaki/go-board` + `@sabaki/sgf` 를 들었다. **이 시점에 후보들의 라이선스·유지보수·Bun 호환성은 확인하지 않았다.**

## 결정
**라이브러리를 쓴다.** 구체 선정은 Phase 1 착수 시 아래를 확인한 뒤 이 ADR 을 Accepted 로 바꾼다.

## 설계 상세

### 평가 절차
| 확인 항목 | 이유 | 방법 |
|---|---|---|
| 라이선스 | 공개 저장소·포트폴리오 사용 가능 여부 | 라이선스 파일·패키지 메타 확인 |
| 유지보수 상태 | 중단된 의존성 회피 | 최근 릴리스·이슈 처리 상황 확인 |
| Bun 호환성 | ADR-004 의 런타임 | 실제로 Bun 에서 설치·실행·시험 |
| 패·자충수·계가 지원 | 원 계획안 1-A 요구 | 규칙 시나리오 시험 세트로 확인 |
| 서버 권위 상태머신과의 접합 | 착수 검증을 서버에서 수행 | 상태 직렬화·복원이 가능한지(재접속·세션 복구와 연결) |
| 기보(SGF) 입출력 | 기보 저장, KataGo 분석 입력 | 라운드트립 시험 |

### 접합 원칙
라이브러리는 **어댑터 인터페이스 뒤**에 둔다. 상태머신은 어댑터 인터페이스만 알아서 라이브러리 교체나 일부 직접 구현으로의 전환이 가능해야 한다.

### 시험 세트
룰 시나리오(패 금지, 자충수 금지, 사석 제거, 계가)를 라이브러리와 무관한 공통 시험으로 작성해 후보 비교와 이후 회귀에 함께 쓴다.

## 대안
- **직접 구현**: 일정 위험. 라이브러리가 요구를 못 채우면 부족한 부분만 직접 구현.

## 위험과 완화
| 위험 | 완화 |
|---|---|
| 후보가 Bun 에서 동작하지 않음 | 어댑터 뒤에서 대체, 필요 시 해당 부분만 직접 구현 |
| 라이선스 비호환 | 선정 단계에서 배제 |

## 검증 방법
공통 룰 시험 세트 통과 + SGF 라운드트립.

## 실서비스라면
핵심 도메인 규칙이면 자체 구현과 철저한 시험을 선호하되, 검증된 라이브러리가 있으면 어댑터로 감싸 쓴다.

## 재검토 조건
후보가 모두 Bun 에서 동작하지 않거나 패·계가를 지원하지 못할 때.

## 관련 ADR
ADR-004, ADR-009
