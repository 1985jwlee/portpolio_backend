# ADR-012: 바둑 룰은 라이브러리로 쓰고 선정은 Phase 1 에서 한다
- 상태: **Accepted (부분 대체: "라이브러리를 쓴다" 결정은 [ADR-034](ADR-034-baduk-rules-engine.md) 가 대체)** — 2026-11-05 정리
- 날짜: 2026-11-03
- 근거: 원 계획안 Phase 1-A, Part 3 확정 사항

## 후속 ADR 과의 관계 (2026-11-05)
ADR-034 가 이 ADR 의 평가 절차를 수행했고(후보 조사·Bun 실측), 그 결과 아래처럼 갈렸다.

| 이 ADR 의 결정 | 상태 | 근거 |
|---|---|---|
| 라이브러리를 쓴다(구체 선정은 Phase 1 에서) | **대체됨** — `packages/baduk-rules` 직접 구현, 라이브러리는 차분 시험 기준(oracle) | ADR-034 결정 1·2 (유지보수·직렬화·타입 기준 미충족) |
| 라이브러리를 어댑터 인터페이스 뒤에 둔다 | **유효** | ADR-034 결정 1 ("어댑터 인터페이스(ADR-012)는 그대로 둔다") |
| 라이브러리 비의존 공통 룰 시험 세트를 먼저 작성한다 | **유효** | ADR-034 "시험 세트(정본, 라이브러리 비의존)" 가 이 ADR 표를 확장 |
| 평가 절차 6단계 | **수행 완료** (결과는 ADR-034 맥락 표) | ADR-034 |

본문 아래는 당시 기록으로 보존한다.

## 맥락
룰 엔진(착수 검증, 패(ko), 자충수, 사석 제거, 계가) 직접 구현은 비용과 버그 위험이 크다. 원 계획안은 **라이브러리 활용으로 확정**했고 후보로 `tenuki`, `@sabaki/go-board` + `@sabaki/sgf` 를 들었다. **이 시점에 후보들의 라이선스·유지보수·Bun 호환성은 확인하지 않았다.** 이 ADR 은 "무엇을 쓸까"보다 **"어떻게 고를까와 어떻게 갈아끼울 수 있게 둘까"** 를 고정한다.

## 결정
- **라이브러리를 쓴다.** 구체 선정은 Phase 1 착수 시 아래 절차를 마친 뒤 이 ADR 을 Accepted 로 바꾼다.
- 라이브러리는 **어댑터 인터페이스 뒤**에 둔다. 서버 권위 상태머신은 어댑터만 안다.
- 룰 검증용 **공통 시험 세트**를 라이브러리와 무관하게 먼저 작성한다.

## 설계 상세

### 평가 절차
| 단계 | 확인 항목 | 이유 | 방법 | 탈락 기준 |
|---|---|---|---|---|
| 1 | 라이선스 | 공개 저장소·포트폴리오 사용 가능 여부 | 라이선스 파일·패키지 메타 | 사용 조건 불명 또는 비호환 |
| 2 | 유지보수 상태 | 중단된 의존성 회피 | 최근 릴리스·이슈 처리 | 장기간 무활동 + 미해결 룰 버그 |
| 3 | Bun 호환성 | ADR-004 의 런타임 | 실제로 Bun 에서 설치·실행 | 실행 불가이며 우회 불가 |
| 4 | 공통 룰 시험 통과 | 요구 기능 충족 | 아래 시험 세트 실행 | 패·자충수·계가 중 하나라도 미지원이고 보완 불가 |
| 5 | 상태 직렬화·복원 | 재접속·세션 복구(ADR-014) | 중간 국면 저장 → 복원 → 이어 두기 | 복원 불가 |
| 6 | SGF 라운드트립 | 기보 저장, 분석 입력(ADR-009) | 기보 → 상태 → 기보 | 정보 손실 |

### 어댑터 인터페이스(개념)
- 새 국면 만들기(판 크기, 규칙, 덤).
- 착수 시도 → **합법/불법 + 이유 + 결과 국면(포획 목록 포함)**.
- 패스, 종료 판정, 계가 결과.
- 국면 직렬화/복원.
- 기보(SGF) 내보내기/가져오기.

어댑터는 라이브러리 객체를 **밖으로 새지 않게** 한다. 서버·프로토콜(공유 타입 패키지)에는 어댑터가 정의한 값 타입만 흐른다 → 라이브러리 교체나 일부 직접 구현이 프로토콜을 바꾸지 않는다.

### 공통 룰 시험 세트(라이브러리 비의존)
| 영역 | 시나리오 |
|---|---|
| 기본 | 빈 곳 착수, 점유된 곳 착수 거절, 차례 위반 |
| 포획 | 단일·다수 돌 포획, 자기 호흡이 없는 착수 중 포획이 동반되면 합법 |
| 자충수 | 포획이 없는 자충수 거절 |
| 패(ko) | 즉시 되따냄 금지, 다른 곳에 둔 뒤에는 허용 |
| 종료 | 연속 패스 종료, 계가(규칙·덤 선택에 따라) |
| 기보 | 알려진 기보 재생 시 결과 일치 |

시험 세트는 후보 비교와 **이후 회귀**에 함께 쓴다. 규칙 변형(일본식·중국식 등)을 지원할지는 미결이다 — 서사상 하나의 규칙으로 시작한다.

### 상태머신과의 접합
서버 권위 상태머신은 (국면, 차례, 시계, 상태) 를 DB 에 영속한다(ADR-014 의 "상태는 프로세스 메모리에 두지 않는다"). 어댑터가 국면을 직렬화하므로 서버 재시작 후 같은 국면에서 이어 둘 수 있어야 한다.

## 대안
- **직접 구현**: 일정 위험. 라이브러리가 요구를 못 채우면 부족한 부분만 어댑터 뒤에서 직접 구현.
- **외부 엔진을 규칙 판정에 사용**: 분석기(KataGo)는 판정기가 아니다(ADR-009).

## 결과
- 얻는 것: 교체 가능성, 규칙 회귀 시험, 일정 위험 완화.
- 치르는 것: 어댑터와 시험 세트를 먼저 만드는 비용.

## 위험과 완화
| 위험 | 완화 |
|---|---|
| 후보가 Bun 에서 동작하지 않음 | 어댑터 뒤에서 대체, 필요 시 해당 부분만 직접 구현 |
| 라이선스 비호환 | 평가 1단계에서 배제 |
| 라이브러리 버그가 규칙 오판 | 공통 시험 세트 + 고정된 버전 |
| 직렬화 불가로 세션 복구 곤란 | 평가 5단계, 안 되면 착수 목록(수순)에서 재생성 |

## 검증 방법
공통 룰 시험 세트 통과 + SGF 라운드트립 + 직렬화 복원 시험. 선정 결과와 탈락 사유를 이 ADR 에 추가한다.

## 실서비스라면
핵심 도메인 규칙이면 자체 구현과 철저한 시험을 선호하되, 검증된 라이브러리가 있으면 어댑터로 감싸 쓴다.

## 재검토 조건
후보 모두 Bun 에서 동작하지 않거나 패·계가를 지원하지 못할 때.

## 관련 ADR
