# ADR-034: 바둑 룰 엔진 — 공유 TS 패키지로 직접 구현하고 라이브러리는 차분 시험 기준으로 쓴다
- 상태: **Accepted** (2026-11-05, 사용자 일괄 확정 U1). ADR-012(룰 라이브러리)의 선정 절차를 수행한 결과다
- 날짜: 2026-11-04
- 근거: ADR-012 평가 절차 / 후보 조사와 Bun 실측(아래) / ADR-009(판정은 룰 엔진) / ADR-014(상태 영속·복원)
- 구현 순서(P0 D24): Phase 1 은 6a~6d 다음이다. 룰 엔진 선정·시험 세트는 Phase 1 설계 재검토에서 확정한다.
- 관련 문서: [phases/01-baduk.md](../design/phases/01-baduk.md) §4

## 맥락
ADR-012 는 "라이브러리를 쓰되 어댑터 뒤에 두고, 부족하면 어댑터 뒤에서 직접 구현"으로 정했다. Phase 1 에서 후보를 조사하고 Bun 에서 실제로 돌려 봤다(2026-11-04, 로컬 WSL2·Bun 1.4.4).

판단 기준(ADR-012 §평가 절차) 중 **유지보수(2)**, **상태 직렬화·복원(5)**, 타입이 어느 후보도 충족하지 못한다(최근 활발한 것은 단순한 gogame.js 뿐이고 계가·자충·직렬화가 제한적). 반면 규칙 자체는 작고 정의가 명확하다(Tromp-Taylor 규칙은 몇 문장).

## 결정 (제안)
1. **룰 엔진은 `packages/baduk-rules` 에 TypeScript 로 직접 구현**한다(불변 판, 포획·자충·**위치 슈퍼코(zobrist 해시)**·패스·종국·영역 계가, 직렬화). 서버와 클라이언트(3D UI 의 불법수 미리보기)가 **같은 코드**를 쓴다. 어댑터 인터페이스(ADR-012)는 그대로 둔다 → 구현 교체 가능. **버전 고정(3차 검토 B12)**: 패키지 상수 `ENGINE_VERSION` 을 대국 시작 시 `game.engine_version` 에 스냅샷하고 그 대국은 같은 버전으로 재생한다, 직렬화 결과에 직렬화 버전 필드 `v` 를 둔다, Zobrist 표는 고정 시드 상수로 만든다(시드 변경 = 엔진 버전 변경), 해시는 64비트를 16진 문자열로 직렬화한다, 클라이언트 엔진 버전이 다르면 클라이언트는 해시 검증을 생략한다. 상세 [phases/01 §3.4](../design/phases/01-baduk.md).
2. **기존 라이브러리는 "차분 시험 기준(oracle)"** 으로 쓴다: 같은 무작위 대국을 직접 구현·tenuki·gogame.js 에 재생해 합법성·포획·점수가 일치하는지 CI 에서 비교한다. 불일치는 사람이 규칙 해석을 판정한다. (선택) KataGo 에 같은 규칙 문자열로 합법성을 묻는 오프라인 비교.
3. **규칙 세트는 둘이다 (U11, 2026-11-05 사용자 결정 — 권장안은 중국식만이었다)**: 도전 개설 시 `rules: chinese | japanese` 를 고른다. 공통은 자충 금지·위치 슈퍼코이고 **`Ruleset` 전략이 계가와 덤 기본값만 다르게 한다**. 중국식은 영역 계가(덤 7.5), 일본식은 **영역(집) 계가 + 사로잡은 돌**(덤 6.5 — 제안, 공식 규정 근거 미확인): 종국 때 사석으로 표시한 돌은 상대의 포획 돌로 가산하고, 시키 안의 빈 점은 누구의 집도 아니며, 착수한 돌은 점수가 아니다. 일본 규정의 3패·장생 무승부는 구현하지 않고 위치 슈퍼코로 순환 착수를 거절한다(대국 설정에 고지). 시키 정의(한 눈 시키·다중 그룹)와 재개 중 수의 감점 처리(D3 로 분쟁을 실제 착수로 풀게 되어 **분쟁 재개 중 자기 집 안 착수**의 처리가 결과에 직접 걸린다)는 착수 시 규정서로 확인한다(**규정서 확인 필요**, 미확인). **판정기를 사람이 교정할 수 있게 한다(3차 검토 B7)**: 일본식 사석 표시는 중립점(시키 안 빈 점) 표시를 함께 받고 표시가 `SekiDetector` 보다 우선하며, 시키 의심 모양은 경고하고 검토 신고를 요구하고, 계가 확인은 표시와 점수 내역을 묶은 `scoreHash` 에 대해 한다. 판정기 신뢰도 확인 전 일본식 레이팅 대국은 보상에서 제외한다(제안). 계가 시한 경과의 "기본 판정"은 두지 않는다(ADR-035 결정 7, D3). 규칙별 차이표·일본식 계가 절차는 [phases/01 §3.5](../design/phases/01-baduk.md).
3a. **무르기는 룰 엔진의 되돌림 연산이 아니라 유효 수열 재생이다**: 엔진은 `replay(config, moves)` 로 처음부터 국면을 다시 만들 뿐 `Board.undo` 를 갖지 않는다. 패 해시 이력·포획 수가 재생으로만 만들어지므로 되돌림 후 상태가 어긋날 수 없다. 무르기 흐름(상대 동의·새 이벤트)은 ADR-035 가 정한다.
4. **SGF 는 `@sabaki/sgf` 를 쓴다**(MIT·활발). 라운드트립은 문자열이 아니라 **의미(노드·속성) 동등성**으로 시험한다. 사석 제안에는 `@sabaki/deadstones` 를 선택적으로 쓴다(합의의 참고, 판정은 아님).

## 시험 세트 (정본, 라이브러리 비의존)
| 영역 | 내용 |
|---|---|
| 규칙별 계가·시키·패 | 중국식·일본식 각각: 영역/집 계가 점수와 내역, 사석 표시 후 사로잡은 돌 가산(일본식), 시키 안 빈 점 제외, 집 안쪽 착수의 득실 차이(중국식 0, 일본식 1집 손실), 단순 패·장생 순환 거절, 중립점(시키) 표시의 점수·`scoreHash` 반영(일본식). 중국식 결과는 일본식 추가 전후 동일(회귀). (이전의 "사석 없음 기본 판정" 시험은 D3 로 기본 판정이 폐기되어 삭제) |
| 기본 규칙 시나리오 | ADR-012 표(점유·차례·포획·자충·패·연속 패스·계가) + 이 문서의 5x5 패 시나리오(실측에 사용) |
| 기보 코퍼스 | 공개 SGF 를 재생해 결과·포획 수 일치(코퍼스는 라이선스 확인 후 선정 — 미확인) |
| 속성 기반 | 무작위 합법수 열: 판 불변식(돌 수 보존, 호흡 계산, 해시 일관성), 직렬화 왕복(버전 필드 포함), 되돌려도 같은 국면(N수 되돌린 뒤 재생 = 처음부터 (수열 − N수) 재생), 재개 표식(`resume`)이 섞인 수열의 재생(표식에서 연속 패스 0) |
| 차분 퍼징 | 직접 구현 vs tenuki vs gogame.js 무작위 대국 N 만 판, 불일치 수집. 일본식 계가는 영역·집 계가를 지원하는 `tenuki` 만 대상(`gogame.js` 는 영역 계가만), 일본식 합법성·포획은 세 구현 모두 |
| 성능 | 19x19 착수 검증 p99 목표(제안 < 1ms, 미측정) |

## 대안과 기각 이유
- **중국식 하나만 (Claude 권장안, 사용자 변경으로 기각)**: 구현·시험이 가장 작았으나 사용자가 일본식도 제공하기로 정했다. 대신 합법성 판정은 공통으로 두고 규칙이 달라지는 곳을 `score`·덤에 한정해 중국식 회귀 위험을 줄였다.
- **A. tenuki 를 주 어댑터로**: 규칙은 가장 풍부하나 2022 이후 변경이 없고 타입·직렬화가 없으며 beta API 다. 서버 권위의 핵심 의존으로 두기에 위험.
- **B. `@sabaki/go-board` + 자체 슈퍼코·계가**: 불변 판은 좋으나 2022 이후 정체이고, 결국 핵심 규칙(슈퍼코·계가)을 자체 구현해야 해 이득이 작다.
- **C(채택안). 직접 구현 + 라이브러리 차분 시험**: 비용은 있으나 서버·클라이언트 공유, 타입·직렬화·해시 통제, 라이브러리를 시험 기준으로 재활용.
- **Go(언어) 서비스로 구현**: 서비스 분리와 타입 공유 포기가 필요하고 룰 엔진은 CPU 부담이 작다(ADR-022 의 ws-gateway 언어 비교와 같은 판단).

## 결과
- 얻는 것: 서버·클라이언트 동일 엔진, 외부 유지보수 위험 제거, 라이브러리를 회귀 기준으로 재활용.
- 치르는 것: 룰 엔진 구현·시험 비용(작지만 정확성이 핵심 → 시험 세트와 차분 퍼징이 필수).

## 위험과 완화
| 위험 | 완화 |
|---|---|
| 규칙 해석 오류 | 차분 퍼징, 코퍼스 재생, KataGo 규칙 비교(선택) |
| 성능 | 해시 기반 슈퍼코, 불변 판의 구조 공유, 19x19 벤치마크 |
| 규칙 변형 요구 | `Ruleset` 전략 객체로 확장(현재 중국식·일본식). 일본식 시키·사석 해석은 규정서 확인 전 보수적 정의 + 사석 합의 단계가 안전장치 |
| 일본식 계가·시키 오판정(결과는 불변이라 사후 수정 불가) | 확정 전 교정 경로(중립점 표시·시키 의심 경고·`scoreHash` 확인), 규칙별 시험 세트, `tenuki` 차분 퍼징, 시키 정의 미확인 항목 명시, 신뢰도 확인 전 일본식 레이팅 보상 제외 |
| 엔진 수정 뒤 과거 대국 재생·해시가 달라짐 | `engine_version` 스냅샷, 직렬화 버전, 고정 Zobrist 시드, 16진 해시 |

## 검증 방법
- 위 시험 세트 전체를 CI 에 포함, 차분 퍼징은 야간 잡.
- Bun 에서 의존성(`@sabaki/sgf`)이 동작하는지 설치 시험(실측 완료).

## 실서비스라면
검증된 엔진(GnuGo/KataGo 규칙 모듈)을 공식 기준으로 삼고 규칙 변형은 규정서 인용으로 관리한다.

## 재검토 조건
직접 구현 비용이 예상을 크게 넘을 때. 활발히 유지되는 TS 룰 라이브러리가 나타날 때.
