# ADR-023: 운영 정책 선제 확정 (임대·백오프, 길이 상한, 보관, 알림, 재구성, 폴백, 백업)
- 상태: Accepted
- 날짜: 2026-11-04
- 근거: 사용자 지시("미결 값을 아키텍처적으로 선제적으로 정한다") / DB·아키텍처·스택 문서의 미결 표 / 사용자 선택 4건(아래)
- 갱신 대상: ADR-007·008·014·020·021, database-schema §11~12, architecture §2·9·10·13, tech-stack §11·13

## 맥락
구현에 들어가면 값은 측정으로 바꿀 수 있어도 **규칙은 구조를 바꾼다**(예: 알림 방식은 서비스 간 결합을, 재구성 방식은 읽기 모델의 구조를 정한다). 그래서 미결 아홉 개를 규칙과 초기값으로 먼저 닫는다. 값은 전부 설정으로 두고 측정 후 바꾼다.

## 설계 상세

### 1. 임대 길이와 재시도 (ADR-021 보강)
**규칙**
- 핸들러 제한시간 ≤ 임대 길이 ÷ 2. 임대 길이 ≥ 처리 p99 × 10. 이 둘이 지켜지면 fencing 거절은 예외 상황이 된다.
- 외부 호출은 트랜잭션 밖(ADR-021)이라 임대 연장(heartbeat)은 M1 에서 두지 않는다. 처리가 임대를 넘기면 실패로 본다.
- 재시도 가능 여부는 오류 분류로 정한다(일시 오류만 재시도, 검증 오류는 즉시 `dead`).

**초기값 (설정)**
| 이름 | 값 |
|---|---|
| `lease_seconds` | 30 |
| `handler_timeout_seconds` | 10 |
| `reaper_interval_seconds` | 10 |
| `retry_base_seconds` / `factor` / `cap_seconds` | 1 / 2 / 300, **완전 지터**(0~지연 균등) |
| `max_attempts` | 8 → 초과 시 `dead` |
| 배치 크기 | 50 (`SKIP LOCKED`) |

재시도 시각은 `next_attempt_at` 컬럼으로 표현한다(database-schema 반영됨).

### 2. 길이 상한 (가정 A-011 확정)
| 대상 | 상한 | 비고 |
|---|---|---|
| 방명록 글 | **500자**, 10줄 | 유니코드 코드포인트 수, 저장 전 NFC 정규화, 앞뒤 공백 제거, 빈 글 거부 |
| 표시 이름 | **2~20자** | 제어 문자·연속 공백 거부 |
| 신고 사유 | 200자 | |
| 반응 | 고정 이모지 **6종** 화이트리스트 | 목록은 코드 상수 + 공유 스키마 |
| DB `CHECK` | 앱 상한의 2배 | 앱 버그가 있어도 DB 가 막는 보조선 |

### 3. 접속 IP — 저장하지 않는다 (ADR-008 갱신)
- 속도 제한은 nginx `limit_req`(메모리)가 접속 주소로, 앱이 세션으로 처리한다. **주소는 DB·로그·지표 어디에도 남기지 않는다.**
- 액세스 로그의 주소 필드는 **마스킹하거나 기록하지 않는다**(nginx `log_format` 에서 제외).
- 감수: 사후에 주소로 차단할 수 없다. 스팸 폭주는 관리자 쓰기 잠금 스위치와 nginx 제한으로 대응한다. 재검토: 스팸이 이것으로 감당되지 않을 때.

### 4. `change_log` 보관
- **1시간 또는 채널당 1만 행 중 먼저 닿는 쪽**까지 보관. 삭제 규칙(`ChangeLogRule`)은 테이블 소유 모듈(realtime)이 등록하고 worker 가 실행한다.
- 재접속 시 클라이언트의 마지막 seq 가 가장 오래된 행보다 앞이면 **스냅샷 경로**(ADR-014). 롤링 배포의 단절 시간(분 단위)을 충분히 덮는다.

### 5. `dead` 보관
- `outbox_event`·`inbox_message` 의 `dead` 는 **30일, 테이블당 1만 건 상한**(초과 시 오래된 것부터). 정상 이력(`published`·`processed`)은 7일 그대로.
- 조사·재투입은 **관리 스크립트**로 한다(`dead` → `new`, 시도 횟수 초기화, 사유 기록). 화면은 만들지 않는다.

### 6. 읽기 모델 재구성 — 그림자 테이블 + 교체
```
1. projection_state 에 (name, status=rebuilding, fence_seq) 기록
2. 새 테이블 <name>_next 를 쓰기 모델 스냅샷으로 채움 (읽기는 계속 기존 테이블)
3. fence_seq 이후 이벤트를 <name>_next 에 따라잡음 (필드별 순번 규칙으로 멱등)
4. 격차가 임계 이하가 되면 한 트랜잭션에서: 기존 ↔ _next 이름 교체 + status=live
5. 이전 테이블은 `<name>_old` 로 이름을 바꿔 보관 후 삭제
```
- 점검 모드 없음, 읽기는 끊기지 않는다. 프로젝터는 재구성 중 **양쪽 테이블에 적용**한다.
- 실행은 `worker` 서브커맨드(`rebuild <projection>`). **M1 의 그림자 교체 대상은 `guestbook_read.entry_view`** 하나다(`my_reaction` 은 같은 잡이 함께 채운다). 나머지는 원천이 다르다: `report_queue` 는 쓰기 모델 `report` 스냅샷으로, `flow_counter` 는 `trace_step` **재집계**(이벤트 재생이 아니며 보관 7일 범위만 복구)로 다시 채운다 — database-schema §5-1.
- 시험: 재구성 중 쓰기가 들어와도 최종 결과가 정본과 같다(AC 로 추가).

### 7. 정적 폴백 — 2단계
| 단계 | 장치 | 덮는 장애 |
|---|---|---|
| 1 | `proxy`(nginx) `error_page 502/503/504` → 빌드 시 생성한 정적 HTML(소개·아키텍처) | 앱·web 컨테이너 다운 |
| 2 | 별도 주소의 정적 대체 페이지(사람이 안내를 갱신하는 수동 전환, design/16) | 집 PC 전원·회선·Funnel 다운 |
- 데모 영역은 폴백에서 제외하고 "일시 중단" 안내를 보인다(ADR-003, FR-070).
- 정적 페이지는 **같은 소스에서 빌드**한다(Next 정적 내보내기 대상 페이지를 한정). 갱신은 배포 시 함께.
- 2단계의 구현 수단(예: Workers 무료 한도 안의 원본 실패 대체 응답)은 **미확인 → 관문 G11.**

### 8. worker→ws-gateway 변경 알림
- `worker` 는 `realtime_read.change_log` 에 쓰고 **같은 트랜잭션에서 `NOTIFY realtime_changed`**(페이로드: 채널·seq 만)를 보낸다.
- `ws-gateway` 는 전용 `LISTEN` 연결로 신호를 받아 `change_log` 를 **마지막 처리 seq 이후로 읽어** 구독자에게 보낸다. 신호가 유실돼도 **1초 폴링**이 보완한다(outbox 방식과 같음).
- 서비스 간 직접 호출이 없고, 여러 인스턴스에서도 같은 방식이며, 재접속 복구가 같은 테이블을 읽는다.

### 9. 백업
| 항목 | 규칙 |
|---|---|
| 대상 | `guestbook`·`identity` 쓰기 스키마(정본). 읽기 모델·로그·outbox 이력은 제외(재생성/휘발) |
| 방식 | 매일 `pg_dump`(커스텀 형식), 백업 컨테이너 또는 호스트 cron |
| 보관 | 일별 7개 + 주별 4개, **DB 볼륨과 다른 경로** |
| 외부 | 암호화한 덤프를 **카드 없이 쓸 수 있는 무료 외부 저장소**에 업로드(대상은 **관문 G12**에서 확정) |
| 복구 시험 | 빈 DB 에 복원해 행 수·무결성 검사를 통과시키고 절차를 `docs/` 에 기록(M1 후반 1회, 이후 분기별) |
- 키(암호화)는 저장소·이미지에 넣지 않는다.
- 백업 결과는 `status/backup/last_run.json` 에 쓰고 worker 의 `StatusFileCollector` 가 `pf_ops_last_success_timestamp{job="backup"}` 로 노출한다. 26시간 넘게 성공이 없으면 Discord 로 경보한다([ADR-027](ADR-027-server-logs.md) 후속 결정, F17 §16~17). 실행은 systemd 타이머(`pf-backup`, 03:30).
- 백업 암호화는 `age`(수신자 공개키만 서버에 둔다, [ADR-026](ADR-026-data-protection.md)).

## 대안과 기각 이유
- **IP 해시 저장**: 분석은 되지만 저장 정책·안내 문구가 필요하고 이 사이트에 이득이 작다.
- **제자리 재구성 + 점검 플래그**: 단순하지만 재구성 중 목록이 비거나 오래된 값이 보인다.
- **내부 HTTP 호출로 알림**: 서비스 간 결합과 재시도 규약이 늘고, 복구 경로와 달라진다.
- **임대 연장(heartbeat)**: 처리가 짧고 외부 호출이 트랜잭션 밖이라 M1 에는 과하다.
- **로컬 백업만**: 디스크 손실에 취약.

## 결과
- 얻는 것: 구조를 바꾸는 규칙이 구현 전에 닫힌다. 값은 설정이라 측정 후 바꿔도 구조가 흔들리지 않는다.
- 치르는 것: 재구성(그림자 교체)·2단계 폴백·외부 백업으로 구현 항목이 늘고, 관문 G11·G12 가 추가된다.

## 위험과 완화
| 위험 | 완화 |
|---|---|
| 초기값이 현실과 안 맞음 | 설정값 + 지표(처리 시간 p99, 재시도 횟수)로 조정, 규칙(임대 ≥ p99×10)을 시험으로 점검 |
| 그림자 교체 중 이벤트 누락 | fence_seq 이후를 양쪽에 적용, 교체 전 격차 검사, 최종 결과를 정본과 대조하는 시험 |
| G11·G12 실패 | 각 실패 시 대안을 정해 둠(1단계 유지, 로컬 + 수동 반출) |
| 주소 미저장으로 사후 차단 불가 | 쓰기 잠금 스위치 + nginx 제한, 필요 시 재검토 |

## 검증 방법
- 임대: 처리를 일부러 임대보다 길게 하여 fencing 거절·재시도·`dead` 이행을 확인.
- 길이: 경계값(500/501자, NFC 결합 문자, 10/11줄) 시험.
- 재구성: 쓰기 부하 중 `rebuild` 후 정본과 읽기 모델 일치.
- 알림: `NOTIFY` 를 막아도 1초 폴링으로 전달됨.
- 백업: 빈 DB 복원 시험.

## 실서비스라면
관리형 Postgres 의 PITR 백업, 메시지 브로커 기반 알림, 오토스케일 임대 튜닝을 쓴다.

## 재검토 조건
처리 p99 가 임대 규칙을 어길 때. 재구성 중 격차가 수렴하지 않을 때. 스팸이 주소 없이 감당되지 않을 때. G11·G12 결과.
