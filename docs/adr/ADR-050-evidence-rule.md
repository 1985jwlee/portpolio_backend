# ADR-050: 증거 규칙 — 스크립트와 원시 결과를 커밋하지 않은 수치는 사실로 쓰지 않는다
- 상태: **Accepted** (2026-11-06, 사용자 결정)
- 날짜: 2026-11-06
- 근거: ADR-013(성능 수치는 측정 후에만 쓴다) · design/08 §9(성능 측정 절차) · design/11 §3(S0 관문 스파이크) · ADR-022 §11.1·ADR-038·ADR-049 의 로컬 실측 표(결과만 있고 재현 스크립트가 저장소에 없음)
- 관련 문서: [design/08 §9](../design/08-test-strategy.md), [design/11 §3](../design/11-implementation-plan.md), [tech-stack §11.1](../domains/tech-stack.md)

## 맥락
이 저장소는 포트폴리오이고 문서의 수치는 곧 주장이다. 그런데 설계 문서의 실측 표 일부는 **결과 숫자만 있고 그것을 만든 스크립트·원시 출력·호스트 사양·커밋 해시가 저장소에 없다.** 읽는 사람이 재현할 수 없고, 작성자 자신도 몇 달 뒤에는 어떤 조건의 수치인지 알 수 없다. ADR-013 은 ‘측정 후에만 쓴다’까지만 정했고 ‘측정의 증거를 남긴다’는 정하지 않았다.

## 결정
1. **스크립트와 원시 결과(및 호스트 사양·커밋 해시)를 저장소에 커밋하지 않은 수치는 문서에 사실로 쓰지 않는다.**
2. **예외는 `참고값(재현 불가)` 로 명시 강등하는 것이다.** 증거가 없는 기존 수치는 지우거나 지어내지 않고 이 표기로만 낮춘다.
3. 수치마다 아래 범례 중 하나를 붙인다.

| 표기 | 뜻 | 쓰는 조건 |
|---|---|---|
| **실측** | 이 저장소의 스크립트로 잰 값 | 스크립트 + 원시 결과 + 호스트 사양 + 커밋 해시가 커밋돼 있다 |
| **추정** | 계산·모델로 구한 값 | 계산 근거(식·입력)가 문서나 코드에 있다 |
| **제안** | 아직 재지 않은 목표·임계 | 측정 전에는 ‘목표’로만 쓴다(ADR-013) |
| **참고값(재현 불가)** | 결과만 남은 과거 수치 | 사실 주장이 아니라 방향 참고로만 쓰고, 재현 스크립트가 생기면 ‘실측’으로 승격한다 |

## 설계 상세

### 범위
`docs/`·`specs/`·`README.md`·ADR 에 적는 모든 측정 수치(지연·처리량·메모리·건수·크기·비교 결과). 코드의 상수나 외부 문서(공식 문서)에서 인용한 값은 대상이 아니며 출처를 링크한다.

### 스파이크 코드 보존 위치
스파이크·측정 코드는 `spikes/` 에 **보존한다**(수치의 증거). 제품 코드가 아니므로 빌드·배포 대상에서는 제외한다. 폴더는 측정 하나당 하나이고 아래를 담는다.

| 파일 | 내용 |
|---|---|
| 실행 스크립트 | 한 줄 명령으로 재실행할 수 있는 것 |
| `results/` 원시 결과 | 요약 전 출력(회별 값) |
| `ENV.md` | 호스트 사양(코어·RAM·OS), 도구 버전, 커밋 해시, 측정 일시 |

### 측정 규칙(design/08 §9)과의 관계
design/08 §9 의 **3회 반복·최악값 판정·커밋 해시 기록**은 이 규칙의 ‘실측’이 갖출 내용이다. §9 는 측정 절차(어떻게 재는가)이고 이 ADR 은 문서에 적는 조건(무엇이 있어야 사실로 쓰는가)이다. 둘은 충돌하지 않으며 §9 는 이 ADR 을 참조한다.

### 위반 시 처리
- 증거 없는 수치를 새로 사실처럼 쓰면 리뷰에서 ‘제안’ 또는 ‘참고값(재현 불가)’ 으로 낮추게 한다. 이미 있는 수치는 삭제하지 않고 강등 표기만 한다.
- 호스트가 다른 값(개발 PC 값)은 ‘실측’ 이어도 호스트 재측정 전에는 합격 근거로 쓰지 않는다(기존 문서의 ‘호스트 재측정’ 표기 유지).

## 대안과 기각 이유
- **문서에 환경 설명만 적는다**: 스크립트가 없으면 재현할 수 없어 같은 문제가 남는다.
- **증거 없는 수치를 모두 삭제한다**: 방향을 알려 주던 정보까지 잃고, 지운 뒤 다시 지어낼 유혹이 생긴다. 강등 표기로 충분하다.
- **CI 가 문서의 수치를 기계 검증한다**: 이 규모에는 과하다. 리뷰 관행으로 시작하고 반복 위반이 있을 때 승격한다.

## 결과 (얻는 것 / 치르는 것)
- 얻는 것: 문서의 수치가 재현 가능한 주장과 참고값으로 구분되어, 채용 담당자가 숫자를 믿을 수 있는 정도를 표기로 안다.
- 치르는 것: 측정마다 스크립트·원시 결과·환경 기록을 커밋해야 해서 측정 비용이 늘고, 기존 표의 강등 작업이 한 번 필요하다.

## 위험과 완화
| 위험 | 완화 |
|---|---|
| 강등 표기가 관행으로 굳어 재측정이 미뤄짐 | 재현 스크립트 작성을 S0·S9 의 작업으로 두고, 승격되면 표기를 ‘실측’ 으로 바꾼다 |
| 원시 결과가 커서 저장소가 부푼다 | 요약 가능한 크기만 커밋하고 큰 원본은 해시와 생성 명령을 남긴다 |

## 검증 방법
문서 리뷰에서 수치 표마다 범례 표기와 증거 경로(`spikes/<이름>/`)가 있는지 본다. 기존 표는 ‘재현 스크립트 필요(결과만 있음) → 참고값’ 주석이 붙어 있어야 한다.

## 실서비스라면
벤치마크 결과를 CI 산출물로 저장하고 회귀 비교를 자동화한다.

## 재검토 조건
강등된 수치가 합격 판정의 근거로 필요해질 때, 측정 비용이 일정을 위협할 때, 반복 위반이 생겨 기계 검증이 필요해질 때.
