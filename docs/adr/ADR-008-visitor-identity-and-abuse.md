# ADR-008: 방문자 신원·악용 방어·보관
- 상태: Accepted
- 날짜: 2026-11-03
- 근거: 명세 FR-010~012·020~024·040~041·080, AC-004~007·009·011, 가정 A-001·A-011 / 인터뷰 R3-Q2, R4-Q4, R5-Q3, R6-Q3·Q4

## 맥락
공개 사이트에서 채용 담당자는 가입 장벽을 만나면 데모를 쓰지 않고 이탈한다. 반면 공개 입력은 스팸·악용에 노출된다. 무료 호스팅에서는 유료 필터를 쓸 수 없고 디스크도 한정적이며, 개인정보는 최소로 가져야 한다.

## 결정
- **익명 세션**(로그인 없이 즉시 사용, 세션별 격리)과 **GitHub 로그인**(영구 신원·표시 이름·본인 글 수정/삭제)을 함께 제공한다. **익명 글은 수정·삭제 불가.**
- 관리자는 본인 GitHub ID **허용목록 1명**.
- 악용 방어는 **속도 제한 + 길이 제한 + 사후 신고·숨김**. 사전 승인과 자동 스팸 점수는 쓰지 않는다.
- 이벤트 시각화는 **내 동작은 상세, 다른 방문자는 내용·식별자 없이 흐름과 개수만** 보인다.
- 방명록 글은 보관, **세션·이벤트 로그는 7일 후 삭제**.

## 설계 상세

### 신원 모델
| 구분 | 발급 | 할 수 있는 것 | 데이터 수명 |
|---|---|---|---|
| 익명 세션 | 첫 접속 시 서버가 발급(예측 불가한 무작위 값, 쿠키는 스크립트 접근 불가·동일 사이트 정책) | 글 작성, 반응, 시각화 | 세션 7일 |
| GitHub 로그인 | OAuth 인가 코드 방식. 요청 권한은 **공개 프로필 읽기 최소** | 위 + 본인 글 수정·삭제, 표시 이름 | 글은 보관 |
| 관리자 | 허용목록에 있는 GitHub ID | 숨김 처리 | |

익명 → 로그인 전환 시 이전 익명 글을 계정에 귀속할지는 구현 시 정한다(미결). 기본은 귀속하지 않는다.

### 악용 방어
| 계층 | 규칙 | 비고 |
|---|---|---|
| 속도 제한 | 세션별·접속 주소별 | 원 접속 주소는 **`proxy` 가 정규화해 넣은 헤더만** 읽는다(클라이언트가 보낸 같은 이름의 헤더는 프록시가 버린다). 터널 경유와 직접 접속 모두 같은 헤더로 보이게 한다(architecture.md §7) |
| 길이 제한 | 글·표시 이름 상한 | 구체 수치는 구현 시 정한다(가정 A-011) |
| 출력 | 글은 **텍스트로만** 렌더. HTML·마크다운 해석 없음 | XSS 방지 |
| 사후 | 신고 → 관리자 숨김 | 숨김은 삭제가 아니라 상태 변경(`visible` / `hidden`) |

### 개인정보
- 접속 주소는 저장하지 않거나, 저장 시 **일 단위로 바뀌는 값과 섞어 해시**한다(제안). 저장 필요성이 확인되면 정한다(미결).
- 지표 레이블에 식별자를 쓰지 않는다(ADR-007).

### 보관 정책
| 데이터 | 보관 |
|---|---|
| 방명록 글·반응 | 보관(숨김 포함) |
| 세션 | 7일 후 삭제 |
| 이벤트 로그·outbox 이력·단계 추적 | 7일 후 삭제 |

정리 작업은 `worker` 가 주기적으로 수행한다.

## 대안과 기각 이유
- **로그인 필수**: 이탈. **공유 데이터·무식별**: 데이터가 섞이고 악용에 취약.
- **사전 승인**: 실시간 데모가 죽는다. **자동 스팸 점수**: 범위가 넓고 오탐 부담.
- **전체 이벤트 공개**: 타인의 글·세션 식별자 노출 위험.

## 결과
- 얻는 것: 낮은 진입 장벽, 인증 구현 증명, 개인정보 최소 보관.
- 치르는 것: 두 신원 경로를 모두 구현·시험해야 한다. 사후 숨김은 노출 시간 창이 있다.

## 위험과 완화
| 위험 | 완화 |
|---|---|
| 스팸 폭주 | 속도 제한, 필요 시 임시 쓰기 잠금 스위치(관리자) |
| 접속 주소 위조 | 터널이 넣어 주는 헤더만 신뢰하고 그 외 경로 차단 |
| 시각화로 타인 정보 유출 | 요약 이벤트는 서버에서 가공 후 전송(클라에서 거르지 않음) — AC-009 |

## 검증 방법
AC-004(익명 수정 403), AC-005(로그인 수정·삭제), AC-006(숨김 권한), AC-007(429), AC-009(프라이버시), AC-011(보관).

## 실서비스라면
신고 큐와 자동 필터를 두고, 데이터 보존 기간을 법무와 정한다.

## 재검토 조건
스팸이 사후 숨김으로 감당되지 않을 때. 요청 권한을 더 줄일 수 있을 때.
