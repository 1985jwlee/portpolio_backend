# ADR-029: 라이선스 — 코드는 MIT, 개인 콘텐츠는 저작권 유보
- 상태: Accepted
- 날짜: 2026-11-04
- 근거: 사용자 결정("MIT + 콘텐츠 저작권 유보") / 저장소가 공개 포트폴리오이고 개인 콘텐츠를 포함함
- 관련 파일: [LICENSE](../../LICENSE), [CONTENT-LICENSE.md](../../CONTENT-LICENSE.md), [design/12](../design/12-content.md)

## 맥락
이 저장소는 라이브러리가 아니라 **포트폴리오**다. 코드와 설계 문서는 보여주려고 공개하는 것이라 참고·재사용을 막을 이유가 작다. 반대로 자기소개·경력·사진 같은 **개인 콘텐츠**는 누가 그대로 복사해 가면 소유자에게 직접 피해가 된다. 라이선스 하나로 둘을 같이 다루면 어느 한쪽이 어색해진다. 또 공개 저장소에 라이선스 파일이 없으면 법적으로는 권리 유보와 같지만 의도가 모호하다.

## 결정
1. **코드, 설정, 설계 문서, ADR 은 MIT** 로 공개한다(`LICENSE`).
2. **개인 콘텐츠는 모든 권리 유보**(All rights reserved)이며 `CONTENT-LICENSE.md` 에 범위를 명시한다: `apps/web/content/**`, 소유자를 설명하는 사이트 변수·프로필 데이터, 사진·로고·이미지 자산(소유자 이름·사진이 든 OG 이미지 포함), 추가될 개인 저술.
3. UI 문자열(`apps/web/src/messages/`)은 코드로 보아 MIT 이다.
4. 서드파티 라이선스는 **참고 목록**으로만 `CONTENT-LICENSE.md` 에 두고 법률 검토가 아님을 밝힌다. Grafana(AGPL-3.0)는 별도 서비스로 수정 없이 쓴다.
5. `.claude/`의 에이전트 엔진 본체는 추적하지 않으므로(`.gitignore`) 이 라이선스의 대상이 아니다.

## 대안과 기각 이유
| 대안 | 기각 이유 |
|---|---|
| 저장소 전체 MIT | 개인 콘텐츠까지 복사·재배포를 허용하게 된다 |
| 전체 All rights reserved | 설계 문서·코드를 참고하게 하려는 포트폴리오 목적과 맞지 않고, 공개 시 라이선스 파일이 오히려 닫힌 인상을 준다 |
| Apache-2.0 | 특허 조항 이득이 이 규모에 작고 NOTICE 관리 부담이 있다 |
| AGPL-3.0 | 채용 담당자가 코드를 살펴보기에도 부담스럽고 포트폴리오에는 과하다 |
| 콘텐츠를 CC BY-NC-ND 로 | 가능하지만 사용자가 "저작권 유보"를 선택했다. 필요하면 후속 ADR 로 바꾼다 |

## 결과
- 얻는 것: 참고·재사용 허용 범위가 명확하고, 개인 콘텐츠가 보호되며, 공개 시점에 LICENSE 가 갖춰진다.
- 치르는 것: 콘텐츠와 코드의 경계를 지켜야 한다. 콘텐츠 파일은 `apps/web/content/` 아래에만 두어야 경계가 선명하다.

## 위험과 완화
| 위험 | 완화 |
|---|---|
| 개인 문구가 코드 영역(예: `messages/`)에 섞임 | `content:check`(12 §1.1)에 소유자 이름·연락처 같은 값이 `content/` 밖에 없는지 점검 항목 추가를 후속으로 검토 |
| 저작권 보유자 이름 오기 | LICENSE 의 보유자 이름은 `git config user.name` 값을 썼으니 공개 전에 사용자가 확인(필요 시 실명/필명 결정) → **확인 완료(2026-11-05): `Jaewoo Lee` 가 맞다(사용자)** |
| 서드파티 라이선스 오해 | 참고용임을 명시, 법률 자문이 필요하면 별도 검토 |

## 검증 방법
- 공개 전: LICENSE·CONTENT-LICENSE 존재, README 의 라이선스 절이 두 파일을 가리킴.
- 의존성 라이선스는 `supply-chain-audit` 점검 시 함께 확인(10 §의존성).

## 실서비스라면
변호사 검토를 거친 라이선스 정책과 자동 라이선스 스캔(SPDX)을 CI 에 둔다.

## 재검토 조건
코드를 다른 사람이 실제로 재사용하기 시작하거나, 콘텐츠에 CC 계열 허용을 주고 싶어질 때.
