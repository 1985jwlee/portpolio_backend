# ADR-011: 정산 통화는 USDC, 시세는 스냅샷 + 견적 유효시간
- 상태: Accepted
- 날짜: 2026-11-03
- 근거: 원 계획안 모순 #1·#2·#3, Phase 5·6

## 맥락
원안은 결제를 SOL, 에스크로를 USDC 로 적어 **통화가 불일치**했다. "실시간 환율"과 "1시간 스냅샷"이 서로 모순이었고, 오프체인 시세 수집을 "오라클"이라 불렀는데 오라클은 보통 온체인 전달을 뜻한다.

## 결정
- 온체인 정산 통화는 **USDC 로 통일**, 환산은 **KRW-USDC** 기준. SOL 은 수수료용으로만 언급한다.
- "실시간"을 쓰지 않고 **스냅샷 + 견적 유효시간(Quote TTL)** 으로 정의하며 **결제 시점 환율을 원장에 기록**한다. 수집 주기는 5~10분.
- 명칭은 **Price Feed(시세 피드)**.
- 모든 결제·정산·포인트는 **모의/테스트넷**이며 README 상단에 명시한다(ADR-015).

## 설계 상세

### 데이터 모델(제안)
| 엔티티 | 핵심 필드 |
|---|---|
| `price_snapshot` | 통화쌍, 환율, 수집 시각, 출처 |
| `quote` | 사용자, 금액, 사용된 스냅샷, **만료 시각** |
| `payment` | 사용된 견적, **결제 시점에 고정된 환율**, 상태 |
| `settlement` | 결제 참조, 정산 통화·금액, 상태, 감사 로그 연결 |

### 규칙
- 견적은 만료 후 사용할 수 없다. 만료된 견적으로 결제하면 거절하고 새 견적을 요구한다.
- 가장 최근 스냅샷이 일정 시간(허용 지연)보다 오래되면 **견적 발급을 거절(fail-closed)** 한다. 허용 지연 값은 시세 소스 확인 후 정한다(현재 수치 없음).
- 수집은 주기 작업(CronJob/스케줄러)이 수행하고 실패 시 이전 스냅샷을 계속 쓰지 않는다.
- 시세 소스의 이용 조건과 가용성은 Phase 5 착수 시 확인한다. 이 시점에는 확인하지 않았다.

## 대안과 기각 이유
- **SOL 결제**: 환율 기준이 KRW-SOL 이 되어 USDC 에스크로와 어긋난다.
- **1시간 스냅샷**: 변동 리스크가 크다.
- **진짜 실시간 스트리밍**: 모의 프로젝트에 과하고, 견적 TTL 로 같은 보장을 더 단순하게 얻는다.

## 결과
- 얻는 것: 정산 통화·환율 기준의 일관성, 감사 가능한 환율 기록.
- 치르는 것: 시세 수집 작업과 견적 만료 처리 구현.

## 위험과 완화
| 위험 | 완화 |
|---|---|
| 시세 소스 장애 | fail-closed, 지표·경보로 노출 |
| 환율이 결제 후 바뀌어 분쟁 | 결제 시점 환율을 원장에 고정 기록 |

## 검증 방법
Phase 5 DoD: 결제 → 에스크로 → 정산 전 과정 재현, 환율 고정 시점이 기록으로 남음. 만료·오래된 스냅샷 거절 시험.

## 실서비스라면
정산 통화는 법무·정산 정책이 정하며 환율 소스는 이중화한다.

## 재검토 조건
Phase 5 착수 시 시세 소스의 이용 조건·가용성 확인 후.

## 관련 ADR
ADR-015(모의 면책), ADR-016
