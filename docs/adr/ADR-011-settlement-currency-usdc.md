# ADR-011: 정산 통화는 USDC, 시세는 스냅샷 + 견적 유효시간
- 상태: Accepted
- 날짜: 2026-11-03
- 근거: 원 계획안 모순 #1·#2·#3, Phase 5·6 / 데이터 구조는 [database-schema.md](../domains/database-schema.md) §10

## 맥락
원안은 결제를 SOL, 에스크로를 USDC 로 적어 **통화가 불일치**했다. "실시간 환율"과 "1시간 스냅샷"이 서로 모순이었고, 오프체인 시세 수집을 "오라클"이라 불렀는데 오라클은 보통 온체인 전달을 뜻한다. 결제 시스템에서 환율은 **분쟁의 근거**가 되므로, "어느 시점의 어떤 환율로 결제됐는가"를 사후에 증명할 수 있어야 한다.

## 결정
- 온체인 정산 통화는 **USDC 로 통일**, 환산은 **KRW-USDC** 기준. SOL 은 수수료용으로만 언급한다.
- "실시간"을 쓰지 않고 **스냅샷 + 견적 유효시간(Quote TTL)** 으로 정의하며 **결제 시점 환율을 원장에 고정 기록**한다. 수집 주기는 5~10분.
- 명칭은 **Price Feed(시세 피드)**.
- 시세가 오래됐거나 없으면 **견적 발급을 거절(fail-closed)** 한다.
- 모든 결제·정산·포인트는 **모의/테스트넷**이며 README 상단에 명시한다(ADR-015).

## 설계 상세

### 용어
| 용어 | 뜻 |
|---|---|
| 스냅샷 | 어느 시각에 수집한 KRW-USDC 환율 한 건 |
| 견적(Quote) | 특정 스냅샷으로 계산한 금액 제안. 만료 시각이 있다 |
| 고정 | 결제 시 견적이 쓴 스냅샷을 결제 기록에 **id 로 묶어** 이후 변하지 않게 하는 것 |

### 데이터 모델
| 엔티티(스키마) | 핵심 필드·제약 |
|---|---|
| `pricefeed.price_snapshot` | 통화쌍, 환율(`numeric`), 수집 시각, 출처. (통화쌍, 수집 시각) 유일 |
| `payment.quote` | 사용자, 금액, **사용한 스냅샷 id**, **만료 시각**, 상태(`open`/`used`/`expired`) |
| `payment.payment` | 견적 id, **고정된 스냅샷 id**, 금액, 상태 |
| `payment.settlement` | 결제 참조, 정산 통화·금액(USDC 최소 단위 정수), 상태 |
| `payment.audit_log` | 추가 전용 |

### 환율 규칙
- 견적 금액 = 원화 금액을 스냅샷 환율로 환산한 값. 환산·반올림 규칙은 한 곳(공용 함수)에 둔다. 반올림 방향과 최소 단위는 Phase 5 착수 시 확정한다(미결).
- **견적은 한 번만 쓸 수 있다**(`used` 이후 재사용 불가). 만료 후에는 쓸 수 없다.
- 결제 확정 시 견적이 쓴 스냅샷 id 를 결제에 복사해 고정한다. **이후 새 스냅샷이 들어와도 기존 결제는 바뀌지 않는다.**
- 가장 최근 스냅샷이 허용 지연보다 오래되면 견적 발급을 거절한다. 허용 지연 값은 **시세 소스 확인 후** 정한다(현재 수치 없음).

### 수집 작업
```mermaid
sequenceDiagram
    participant J as 주기 작업
    participant S as 시세 소스
    participant D as postgres

    J->>S: 환율 조회
    alt 성공
        S-->>J: 환율
        J->>D: 스냅샷 삽입 (통화쌍 + 수집 시각 유일)
    else 실패 또는 비정상 값
        J->>D: 삽입하지 않음, 실패 지표 상승
    end
```
- 실패해도 **이전 스냅샷을 새 것처럼 쓰지 않는다.** 오래되면 fail-closed 가 작동한다.
- **비정상 값 방어**: 직전 값과의 괴리가 허용 범위를 넘으면 삽입을 보류하고 경보한다. 허용 범위는 소스 특성 확인 후 정한다(미결).
- 시세 소스의 이용 조건·호출 한도·가용성은 Phase 5 착수 시 확인한다. **이 시점에는 확인하지 않았다.**

### 감사
결제·정산 상태 전이는 모두 추가 전용 감사 로그에 남긴다. "이 결제는 몇 시 몇 분 스냅샷의 환율로 확정됐다"를 한 질의로 보일 수 있어야 한다(Phase 5 DoD).

## 대안과 기각 이유
- **SOL 결제**: 환율 기준이 KRW-SOL 이 되어 USDC 에스크로와 어긋난다.
- **1시간 스냅샷**: 변동 리스크가 크다.
- **진짜 실시간 스트리밍**: 모의 프로젝트에 과하고, 견적 TTL 로 같은 보장을 더 단순하게 얻는다.
- **오래된 시세로 계속 견적**: 편하지만 잘못된 가격으로 결제될 수 있어 fail-open 은 채택하지 않는다.

## 결과
- 얻는 것: 정산 통화·환율 기준의 일관성, 감사 가능한 환율 기록, 장애 시 안전한 실패.
- 치르는 것: 시세 수집 작업과 견적 만료 처리 구현. 시세 장애 시 결제 불가(의도된 동작).

## 위험과 완화
| 위험 | 완화 |
|---|---|
| 시세 소스 장애 | fail-closed, 지표·경보 |
| 시세 소스의 비정상 값 | 괴리 검사, 삽입 보류 |
| 환율이 결제 후 바뀌어 분쟁 | 결제 시점 스냅샷 고정 기록 |
| 반올림 규칙 불일치로 금액 오차 | 환산 함수 단일화 + 속성 시험 |

## 검증 방법
Phase 5 DoD: 결제 → 에스크로 → 정산 전 과정 재현, 환율 고정 시점 기록. 시험:
| 시나리오 | 기대 |
|---|---|
| 만료된 견적으로 결제 | 거절, 새 견적 요구 |
| 같은 견적으로 두 번 결제 | 두 번째 거절 |
| 스냅샷 수집 실패가 허용 지연을 넘음 | 견적 발급 거절 |
| 결제 후 새 스냅샷 수집 | 기존 결제의 환율 불변 |
| 비정상 값 주입 | 삽입 보류 + 경보 |

## 실서비스라면
정산 통화는 법무·정산 정책이 정하며 환율 소스는 이중화한다.

## 재검토 조건
Phase 5 착수 시 시세 소스의 이용 조건·가용성 확인 후.

## 관련 ADR
ADR-015(모의 면책), ADR-016, ADR-017
